# The UI (`qml/`)

The `qml/` folder is the entire visible application. It reads the library, launch state, theme and settings from C++ singletons, and delegates every write back through those singletons — no QML file touches a file or spawns a process directly. The C++ side is documented per folder in `docs/code/`; this doc covers what the QML does with it.

## Windows

There are three windows:

- **`Main.qml`** is the `ApplicationWindow` that opens at startup. It holds the rail, the game list, the details view and the setup guide overlay. The game editor opens inside it as a dialog.
- **`SettingsWindow.qml`** is a separate `ApplicationWindow` created the first time Settings is opened and kept alive afterwards. It is non-modal so the main window updates live while a theme is edited.
- **`BulkLookup.qml`** ("Look up missing info") is its own `ApplicationWindow` with its own window frame and controls, created the first time it opens.

All three windows are frameless (`Qt.FramelessWindowHint`): the system title bar is replaced by `WindowControls` (the three buttons, top-right) and `WindowFrame` (resize edges). Each window moves only by dragging its title strip (the strip above the hero, the page description in settings), never empty space elsewhere.

## Data flow

QML reads the library and app state through C++ singletons exposed to every file as global names:

| Singleton | What it gives QML |
|---|---|
| `Library` | The game list model, platform and tag lists, search/filter state, emulator choices, write operations |
| `GameRunner` | Running games, launch, the Steam-running flag |
| `Theme` | Every visual value, the active theme, live editing |
| `Actions` | Named action keys, triggering actions, the model for the Keyboard page |
| `Metadata` | Lookup progress, art downloads, `discardDownloads()` |
| `Backups` | Last backups, backup and restore jobs |
| `General` | Startup settings (fullscreen, login), session length, Reduce motion |

QML never stores data from these in its own properties except as a last resort (a pending value while a save is in flight, or a value being animated). The source of truth is always the C++ side.

## Named actions

Keyboard shortcuts and menu entries go through **named actions** rather than hard-coded `Shortcut` or `Keys` handlers. Every action is declared in `actionschema.cpp` with a group, a title, and default keys; `[shortcuts]` in `settings.toml` overrides them. `Actions.trigger(name)` signals `Actions.triggered(name)`, which each window catches in its `run(name)` function.

`ActionShortcuts` (a thin `Item`) creates one `Shortcut` per action a window handles. Its `scope` is `"main"` or `"settings"` — actions that work in both windows are included in either — and its optional `only` list restricts which actions fire while the setup guide covers the window.

`run(name)` in Main.qml handles app-wide and list/detail actions. `runOn(name, game)` is the same for "selected game" actions: both the selected game and a game's right-click menu arrive there, so the logic lives in one place. SettingsWindow has its own `run(name)`.

`Actions.recording` turns shortcuts off while the Keyboard page waits for a key press; the pressed key reaches the recording row's `Keys` handler instead.

## Lazy loading

Startup must reach the first frame quickly (the target is 400 ms), so secondary views are loaded on demand via `Loader`. Nothing is created until it's first needed:

- The game editor, detailed lookup, art browser, game menu, app menu, about dialog, filter panel, Steam prompts, locate picker, setup guide, play history popup and statistics page are all `Loader { active: false }` in Main.qml, activated the first time their function is called.
- SettingsWindow is created the first time `openSettings()` runs, and BulkLookup the first time `openBulkLookup()` runs, each with `createWindow(url)` (`Qt.createComponent()` and `createObject()`). Nothing keeps the `Component`, so Qt can drop the compiled file later.
- The setup guide's step pages are loaded on first visit and kept, so Back returns to what was entered.
- Inside the settings window, each category page is its own file, loaded when the category is first selected (a `PageLoader`, whose `item` is the page) and kept while the window is open, so it keeps its scroll position and fields. Closing the window unloads every page but the open one and calls `WindowState.releaseMemory()`: all pages together hold about 150 MB. The page you leave slides out as the new one slides into its place (see [Settings window](#settings-window)).
- The backdrop's `SetupBackdrop` loads with the setup guide, not at startup.

**A `Loader` names its file, not its type.** Write `source: "views/GameEditor.qml"`, never `sourceComponent: GameEditor { … }`: an inline type is resolved when the file containing the `Loader` loads, so every file the view uses loads before the first frame even though the view is closed (102 of the 134 files did, until this was fixed). What the inline type used to set moves out of it:

- signal handlers go in a `Connections { target: loader.item }`;
- one-off values go in `onLoaded` or `setSource(url, { … })`;
- bindings that must stay live go in a `Binding { target: loader.item; … }`.

Loading stays synchronous, so a function can use `loader.item` right after setting `active = true`. A view that only a hidden menu needs gets its own file for the same reason (`LogoMenu.qml`, which the hero's inline menu used to be).

What is loaded immediately: Rail, GameList, Hero, and Backdrop, plus `GameDetails` in List view or `GameGrid` in Grid view — everything visible on the first frame. Each view creates the other only when it is needed: Main holds `GameDetails` in a `Component`, shown by a `Loader` beside the list (List view only) and by a second one inside the full-window game page that Open game page shows over the grid (created on first use and dropped when the view switches back to List).

## Main window layout

The main window is three columns side by side:

```
┌──────┬─────────────┬───────────────────┐
│ Rail │  Game list  │   Game details    │
│      │  (search,   │  (hero, actions,  │
│      │   rows)     │   info, tags)     │
└──────┴─────────────┴───────────────────┘
```

**Rail** (`Rail.qml`) is the left icon strip: the logo (with its app menu), an "All games" button, one button per platform, and the Steam friends, add and settings buttons at the bottom; the platform buttons sit in a `Flickable` between them, scrolled by the wheel only (a press-and-drag on a button reorders it), scrolled to keep the selected platform in view (`showSelected()`), and scrolled by a drag held near its top or bottom edge (`scrollDuringDrag()`). All of these jump rather than ease, so a held key or the wheel never lags. `Library.platforms` leaves out platforms with `in_rail = false`. Right-clicking a platform button (`RailButton.hasMenu`, `menuRequested`) opens `PlatformMenu` right of the rail, lazily loaded, its top level with the button's like the logo's `AppMenu`; right-clicking another button while it shows closes it and opens that one's once it is gone (`platformMenu.next`), as reopening a closing popup only moves it; the button stays highlighted while it shows (`menuOpen`). "Edit platform" opens Settings → Platforms with its row expanded (`editPlatform`), and "Hide from the rail" writes `in_rail = false`, clears the platform filter if it was that platform, and hands the toast an Undo (`undoable`). Right-clicking the rail's empty space (a `MouseArea` under the buttons that takes only the right button, so the buttons' own presses and the platform menus come first) opens `RailMenu` the same way, its top level with the press: a check row per platform with games (`CheckRow`, not a `MenuItem`, so a click leaves the menu open; the rows are counted, not bound to the list, so a toggle doesn't rebuild them) (`Library.platformSettings`) that flips `in_rail` (hiding the selected platform clears the filter), then the bottom buttons, which flip `General.railHiddenButtons`. The `LATTIS_RAIL_MENU=1` hook opens it. It draws as a floating rounded panel or a plain full-height bar based on `rail.container`. Clicking the logo opens `AppMenu`; `app_menu` / F10 does the same. The menu's Hide rail / Show rail entry runs `toggle_rail`, which flips `General.railHidden`. The rail keeps its slot in `Main.qml`'s `RowLayout`: `shown` (eased at `motion.normal`, instant at startup and with Reduce motion) fades everything but the logo (the "All games" button sets `easeOpacity: false` so it follows `shown` instead of easing it a second time and lagging; a spacer holds it at the top once the platforms have faded out of the layout), and while hidden the buttons and the right-click area are disabled and a drag in progress is cancelled. The logo moves right by half of `list.padding` so its gaps match. A platform button can be dragged to a new place in the rail: `RailButton` (with `draggable`) arms after the press has been held still for `rail.drag_hold` ms, then reports the pointer (`dragStarted`, `dragMoved`, `dragEnded(dropped)`), and the Rail keeps the drag (`dragFrom`, `dragTo`, `dragDy`): the others slide aside (`shiftOf()`), a line shows the slot, and a drop calls `Library.movePlatformBefore(id, <the platform now after it>)`, since the rail lists only platforms with games and a step count wouldn't mean the same in the file. Esc, a drop outside the panel or a reload of `Library.platforms` ends it. `Settings → Platforms` has the same with a handle on each defined row (`PlatformRow.handle`, only while the search is empty), through the settings window's shared drag (below); a drop there is written inside `SettingsWindow.change()`, so its Undo shows in that window. The `LATTIS_DRAG_PLATFORM=<id>:<pixels>` hook shows either mid-drag. The bottom buttons (`bottomDefs`, shown in `General.railButtonOrder` without the hidden ones, and without `steam_friends` while Steam isn't found) drag the same way among themselves, with the drag state under `bottom*` names; a drop calls `General.setRailButtonOrder()`, keeping the other buttons' places. The Steam friends button draws `RailFriendsFace` over its `RailButton`, loaded after the first frame, and opens `SteamStatusMenu` right of the rail; `AppMenu` has a fixed layout of its own and does not follow the rail's button order.

**GameList** (`GameList.qml`) shows the search row (`LibrarySearchRow`, below) and the scrollable list of games and group headers. `revealGame(id)` (also in `GameGrid`) brings a game into the list before selecting it, changing as little as it can: it expands the collapsed group holding it (`Library.expandToGame`), turns Installed only off only for a game that isn't installed, then clears the filters, then leaves the collection. While a collection is open a banner between the chips and the list gives its name, its game count and a "Leave the collection" button (`[collections]` banner values); with it open Installed *on* is the chip ("Installed only"), not Installed off. Typing in the list continues the search; arrow keys and Enter still reach list actions while typing. The filter panel (`FilterPanel`) opens beside the filter button, not modally. The list part (rows, scrollbar, highlight, empty label, selection bar and the list's background) reaches `reach` left of where the layout puts it, over the rail's slot, and starts `extraTop` lower; the search row and chips don't move. The chip row sits in a container (`chipRow`) that takes its space the moment the first filter turns on, and gives it up in two steps when the last turns off: the chip pops out, then the list eases up (`chipRow.space`, in and out, at `motion.normal`). `Main.qml` binds both to `General.railHidden` (`list.rail_hidden_margin`, `rail_hidden_top_margin` while hidden, `rail_margin`, `rail_top_margin` while shown) and they ease. The rows fade out at the top and bottom edges while there is more to scroll to (`list.edge_fade`). While the rail is hidden the platform shows as the first filter chip (× returns to All), lights the filter button's badge and is cleared by `clear_filters`; `Library.filtersActive` and `clearFilters()` don't count it, so nothing changes with the rail shown. Printable characters typed anywhere in the list start or extend the search. Escape in the list clears the selection first when several games are selected, then the search; Escape in the search box collapses back to the list. While Up or Down (`previous_game`, `next_game`) repeats from a held key, the selection moves but `currentGame`, so the details, stays put (`detailsHeld`) and catches up on the key's release, which reaches the list's `Keys.onReleased` (a `Shortcut` takes only presses; repeats are auto-repeat release and press pairs). Losing focus counts as a release. A game added to or removed from the list fades and slides (`list.change_slide`) while the rows after it move over (`add`, `remove` and `displaced` transitions). A group collapsing or expanding (announced by the model as `Library.groupChange` just before it sends the rows: the first row and the signed count, empty again after half a second) folds instead, over `list.fold_duration` for a block as tall as the list and less for a shorter one (by the square root of the ratio, at least `motion.normal`), so a group of one game doesn't crawl: everything after the group's header moves as one block, the group's rows sliding up under the header (collapsing) or down out from under it (expanding), with the rows below attached. The list's transitions stand down for it; every row after the header follows one shared offset, `foldShift`, so rows the list creates while it runs land in the block too. Removed rows are held by a remove transition that only waits out the fold (`foldRemove`), not by `ListView.delayRemove`, which keeps the rows after a delayed row below it and so opened a gap the height of the group. The block moves at most the height left below the header, rounded up to whole rows, so a group of hundreds folds as quickly as one of three; rows of a collapsing group that were off screen never show, and a row fades out over the half row before its middle, where its text is, reaches the header's bottom edge (and in the same way), so it never shows over the header's title, the header having no background. A search, filter or sort resets the model instead and animates nothing.

**LibrarySearchRow** (`LibrarySearchRow.qml`) is the top of both the list and the grid: the search box, the filter and collections buttons with their lazy popups (`[search] button_spacing` is the gap between them; `[search] joined_buttons` draws them inside the search box's background: one `Surface` behind the row, the buttons and the field transparent, no gap), the filter chips and the open collection's banner, with `activeFilters`, `openFilters()`, `openCollections()` and `askCollection()` (the collection and Steam-import dialogs load on first use). `field` is the search `TextField`; `focusRequested` asks the host to focus its view (Escape in the box), `message` carries toasts. `reach` and `extraTop` shift the banner as the list shifts its part. The grid sets `showChips: false` (no chip row) and `inlineWidth`, which moves the banner into the button row, as tall as the buttons: the search box and buttons keep `inlineWidth` between them and the banner takes the rest.

**GameGrid** (`GameGrid.qml`) is the Grid view's cover wall (`General.view = "grid"`; Main creates it through a `Loader` and `Main.browser` is whichever of it and `GameList` is showing). `Main.qml` sets `Library.flat` while the grid is the view (not GameGrid itself: a `Binding` destroyed with the Loader item does not restore the value), so the model has no header rows and the sort order runs across platforms. It starts from the list's selection (`selectedId` and `selection` bound to `gameList`'s until the grid picks its own), and Main keeps the grid's in `gridSelection` to hand back to the list when the view switches, since the grid may be gone by then. It has the same selection API as `GameList` (`currentGame`, `selectedId`, `selection`, `selectGame`, `revealGame`, `selectGames`, `run(name)`, `openMenu`, `openMenuBelow`, `neighborOf`, `neighborOutside`, `clearSelection`, `focusList`, `scrollThrough`), so `Main.qml` talks to either. The search row sits at the top left, with no filter chips and the open collection's banner beside the buttons (the row grows to make room, up to `toolbarLeft`, so the banner never runs under the toolbar); under it a `GridView` over `Library`, whose first row of covers is level with the hero of the list view's game page (`contentTop`). `coverWidth` (`General.gridCoverWidth`) is a target: `columns` is how many fit with `grid.gap`, never fewer than one, and `cellW` stretches so the last column ends at `grid.margin` (`usable` adds one gap to the width and takes the margins off). Covers are 2:3, `PreserveAspectCrop`, `grid.radius`, decoded at the cell's size in device pixels rounded up to a 32 px step (`sourceSize`), a `FadeImage` with `cache: true` and `retainOnResize`, so a resize keeps the old picture up while the new size decodes; a game with no cover shows its title on an `ArtPlaceholder` in its hue, which also stands in while a cover loads and stays until it has faded in (`FadeImage.arriving`; hidden as soon as the picture was ready, it left a blank while the cover faded in from nothing). Badges at the top right (`grid.badge_*`): favorite, update waiting, running. Uninstalled and hidden games take `list.uninstalled_opacity`. The current game has a ring outside the cover (`grid.ring_*`), other selected covers the same ring at `grid.selected_opacity`; the cover under the pointer gets `grid.hover_overlay` (a `Surface`: `hover_overlay_end` and `hover_gradient_direction` make it a gradient) and a pointer cursor, `grid.play_button` (`center` or `corner`) adds a Play button (a circle, or a pill when `play_button_label` isn't empty, with that text beside the icon) (`play_button_margin` from the edges in the corner) above the cover's `MouseArea` (its own, so `hovered` also counts it) that selects the game and emits `launchRequested`, hidden while the game runs, and `grid.platform_icon` (`hover` or `always`) a `Badge` at the top left (`platform_icon_margin`; the top right badges use `badge_margin`) with the game's platform icon (the model's `platformIcon` role, `Icons.forPlatform`), and dips to `motion.press_scale` while pressed. The cover's picture grows to `grid.hover_zoom` (default 1.025; 1 = off) under the pointer over `motion.normal`, inside the cover's clip, so the cell, ring and badges stay put (not with Reduce motion). Titles show under covers with `General.gridShowTitles`, otherwise as a tooltip. Click selects (Ctrl/Shift build the multi-selection as in the list), double-click launches, right-click opens `GameMenu`. Left and Right move by one, Up and Down (`previous_game`, `next_game`) by a row, staying in the column and landing on the last cover of a shorter row, Page Up/Down by the visible rows, Home/End to the ends, with Shift extending the selection; the view jumps to contain the current cover (`positionViewAtIndex`), never scrolling animated. The size slider is a pill at the bottom centre (`PopoverBackground`, `radius.pill`: − button, `SettingsSlider`, + button) setting `coverWidth` live between `grid.min_cover_width` and `grid.max_cover_width`; Ctrl+wheel and the `grid_bigger` / `grid_smaller` actions step it one column count at a time (the width that gives `columns` ± 1, kept within the saved range of 80 to 600 rather than the slider's, so the steps never stick or come back unevenly). The width is saved 400 ms after the last change (`saveTimer`) and the view keeps the current cover in sight while the cells change size. When a zoom or the side panel opening or closing changes the cell width, the covers slide to their new places over `motion.normal` (`reflowing`, set by `reflow()`; a window resize doesn't set it, so covers don't trail a drag or move as the window settles at launch). The view positions cells from C++, which a `Behavior` on `x` or `y` never sees, so each cell watches its own `x` and `y` and is drawn at its old place through a `Translate` that animates to zero. A cover that changes rows fades in at its new place instead, growing from `motion.reflow_scale` about its center (`arrive`), since sliding there would cross the other covers on a diagonal; a cell the view just created or reused takes its place without sliding. The grid's bottom margin is the pill's height plus `grid.margin`, so the last row scrolls clear of it. While two or more games are selected, the "N selected" bar (also a pill) takes the slider's place. Measured on a 1000-game library scrolled at 2500 px/s at the smallest size: median frame 3 ms, one frame over 25 ms, so there are no cover thumbnails. `Main.switchView()` changes `General.view` behind a snapshot of the old view, and shows the new one only once it is whole. A view is made fresh on every switch, so it arrives cold: placeholders first, then covers, the panel's logo and the hero's art as they load. Revealed at once, those steps showed one after the other. So the switch grabs `viewArea` (the window background, the backdrop and `libraryLayout`, not the toolbar or window controls, which stay live) and waits until that image can be drawn (`coverView()`; switching before would show the new view half-made). Then it covers the window with it (`viewCover`), switches, and keeps it there while `viewCovered` is true: a `FrameAnimation` (`viewWait`) checks each frame whether the new view's art is in (`newViewReady()`: `GameGrid.artReady()`, the covers in sight and the panel's logo; `GameDetails.heroLoading` for the list), up to `motion.view_switch_wait` ms. Meanwhile the covers (`GameGrid.coverFades`) and the hero's art (`Hero.entering`) load without their own fade-in, so they show whole. `revealView()` then fades the snapshot out, linear over `motion.fast`, blurring it up to `motion.view_switch_blur` px as it goes (so the two views don't show sharp over each other), while the new view's content (the grid, or the list and details, never the rail) rises `motion.view_switch_rise` px into place over `motion.normal` (`viewRise`; not with Reduce motion, which keeps the fade). A second switch during the wait reveals the first at once. No snapshot with fades off, over the setup guide, or with a full page covering the library. The covers fade out at the bottom edge while there is more to scroll to (`grid.edge_fade`, default `list.edge_fade`), and at the top once scrolled when `grid.edge_fade_top` is on (off by default).

The side panel is a **GridPanel** child of `GameGrid`, on the right: its top lines up with the first row of covers (`grid.margin` under the grid's top), its bottom is `grid.panel_margin` above the window's, and the grid is that much narrower while the panel is wanted. It is wanted when `General.gridPanel` is on and there is a current game (`panelWanted`); with none (an empty grid) it hides without touching the setting. Showing or hiding narrows or widens the grid at once and slides the panel in or out over `motion.normal` (`slide`, whose `Behavior` is off with reduced motion and before the first frame), so the covers reflow once while the panel moves; the panel is drawn above the grid, so covers grow under it as it leaves. On a panel toggle each cover also starts drawn at its old size and scales to the new one as it slides (`coversResized`, a `Scale` on the whole cell from its top-left, so the Play button, badges and title stay on the cover); a live resize or zoom changes the size at once. `Main` toggles it with `toggle_grid_panel` and a plain icon button left of the window controls (`panelButton`); the toolbar keeps clear of it. While the grid shows, `Main`'s `Backdrop` covers the whole window and follows the current game after `hero.load_delay` (`gridHeroGame`), the same delay the hero's picks wait.

**GridPanel** (`GridPanel.qml`, `[grid] panel_*`) shows the current game: its logo aspect-fitted, as tall as the logo's shape allows up to `panel_logo_height` (a wide logo ends at the panel's width instead; the height comes from the logo's aspect, kept from the last logo until the next one loads, `panel_logo_gap` separates it from Launch, `panel_logo_top_gap` adds space above it and `panel_buttons_gap` under Properties and More; the title at `font.title_size` when there is none), a full-width `GameLaunchButton`, two bordered buttons (Properties and More, which opens `GameMenu` under itself through `GameGrid.openMenuBelow()`), then a flickable that scrolls under them. In it, the chips in columns over the panel's width (a `GridLayout`), their content aligned left: in a strip (`chip_style = strip`) the chips fill equal columns with no gap over one `Surface`, a Repeater drawing the dividers from each cell's column and row, and each `FieldChip` has `inStrip` (no fill or border of its own unless it needs attention, `valueFirst` and the `strip_*` sizes and colors through `StatChip`'s `valueFontSize`, `labelColor`… properties); chips in cards fill equal columns spaced like Properties and More, while bare chips keep their own width (`fitWidth`) and the space left over is shared equally between the columns (`spread`), so the first column starts at the left edge and the last ends at the right. Up to three columns, as many as the widest shown chip's content allows (`StatChip.fitWidth`, measured again when a chip's value changes, so a long value can drop a column), then balanced over the rows (four chips go 2 + 2); a chip with no visible surface (no fill, no border) drops its padding (`StatChip.contentInset`) so its icon lines up with the buttons' edge, then a one-column grid of the panels in the order of `General.gamePageGridPanels`: `InfoPanel`, `FriendsPanel` and `AchievementsPanel` (given `panels: General.gamePageGridPanels`, which their `wanted` reads instead of the page's list) and the game's tags (a caps "Tags" label and `TagChip`s that filter by the tag). Its own `GameFields` has `chipNames: General.gamePageGridChips`, so what a field reads or asks for follows the grid's chips and not the page's. The chips are `FieldChip`s (`carded`, with `chip_style = cards`, gives each its own card, `chip_background`, `chip_border` and `chip_border_width`, (and, with the info, Friends and Achievements panels, `fillOpacity: Theme.grid.cardOpacity`, a `Surface` property that scales its fill's alpha) in place of `stat_chip`'s look; the game page's chips never do); `GameLaunchButton` and `SettingsButton` take the panel's `launch_*` and `button_*` settings through their `buttonHeight`, `idleLabel`, `cornerRadius`… properties, which follow the page's look by default; `panel_logo_min_height` is the logo box's least height, a smaller logo centered in it; the list of them is replaced only when the set of shown chips changes, so another game's values change in place. Right-clicking the chips opens `GamePageMenu` with `place` `grid_chips`, right-clicking a panel with `grid_panels` (all four, tags included), writing the grid's lists. `LATTIS_GAME_PAGE_MENU=<chips|info_rows>` opens either, and `LATTIS_GAME_MENU=page` the More menu. "Open game page" (a `TextLink` pinned under the scrolling part, `pageRequested`) and the same entry of `GameMenu` in Grid view run `window.setGamePageOpen(true)`: `GameDetails` as a full page over the grid with Back to games (or Escape), hiding the rail and the grid once it covers them. The two take turns over the shared backdrop instead of crossfading, which showed both layouts at once: `gamePageShown` runs linearly over `motion.normal`, the grid (one layer, with the panel button) is gone by 60% of it, and the page fades in from 40% while rising `details.page_offset` px, by the square of what is left, so closing sinks it on the same curve and turning back halfway does not jump; the toolbar glides between the grid's left edge and the page's with it; `Main.details` is whichever `GameDetails` exists, and `activateOn()` creates the page's one when a grid action (favorite, open folder…) needs `GameDetails.activate()` while the page is closed. Switching views (`toggle_view`, `Main.switchView()`, under GameGrid above) hides the new view behind a snapshot of the old one until its art is in, then fades the snapshot out as the new view rises into place; Settings and the setup guide set the view without it. Its content fades out at the bottom edge while there is more to scroll to (`grid.panel_edge_fade`, default `grid.edge_fade`), and at the top when `grid.edge_fade_top` is on.

**FieldChip** (`FieldChip.qml`) is the `StatChip` of one field of a `GameFields` (its icon, value, tooltip and click); `GameDetails`' chip row and `GridPanel` both use it, each handing it its own `GameFields` and a `SteamPendingMenu`. **GameLaunchButton** (`GameLaunchButton.qml`) is the `LaunchButton` for a `game` (installed, update, running, locatable, and the missing emulator that Launch installs, with its install dialog and the failure message), likewise shared by `GameDetails` and `GridPanel`.

GameList keeps a **multi-selection**: `selection` (a map of ids; empty with fewer than two games), `selectionCount`, and `anchorId` (the last plain or Ctrl click). `selectedIds()` is the selection, or the current game alone. Ctrl+click toggles, Shift+click selects the range between the anchor and the click over the visible game rows, and `extend(step)` is Shift+Up/Down (`extend_previous`, `extend_next`; `select_all`; `clear_selection` has no default key, as Escape is handled in the list's key handler so a global Escape shortcut doesn't take it from dialogs and the search box). `syncSelection()` drops ids that left the list after a reset, and a change of search, filters or platform clears the selection. With two or more selected, a bar ("N selected", × to clear) takes the place of the filtered-count line (`list.selection_bar_*`).

**GameMenu** has a selection mode: `games` holds the selected games when the menu was opened on one of them (`multi`), and `game` is the one clicked. It then shows only Favorites, Tags, Emulator and Hide/Unhide, acting through `Library.setGamesValue` and `Library.retagGames`, which make one Undo. Tags rows are plain items rather than `MenuItem`s, since those close the menu; each shows on, off or mixed (`tagStates`) and a pick adds to every game unless all have it. "New tag" emits `newTagRequested(ids)`, which Main opens as **NewTagPrompt** (a name field; lazy). **Collections** (one game or a selection) is a submenu like Tags, with a check, dash or empty box per collection from `Library.collectionStates` (refreshed when the games, the collections or a toggle change) and **New collection**, which emits `newCollectionRequested(ids)`; unchecking the open collection there takes the games out of it. Separators split the menu into organize, open, manage and hide/uninstall groups; the ones that would only bound empty groups hide in selection mode. Emulator is enabled when every game is a ROM game of one platform; otherwise its title says why, as a disabled entry gets no hover for a tooltip. `LATTIS_SELECT_GAMES` and `LATTIS_GAME_MENU` show them. For one game, **Same game as** (shown when `Library.sameGameCandidates` finds any and the game isn't linked) links it to another copy, and **Unlink** replaces it on a linked game; **PlayHistoryPopup** then keys its rows by each session's `key` and deletes and restores a session through its own `gameId`.

The menu lives in `GameList`, which opens it three ways, all through `prepareMenu(row)` (the game, the selection when the game is part of it, and `menuRow` for the hover highlight): a right-click opens it at the pointer, `game_menu` under the row (`openMenu(row)`), and the `menu` button on the game's page (⋯, in `[game_page] buttons`) under that button: `GameDetails.menuRequested(button)`, which Main hands to `openMenuBelow(row, item)`. That one lines the menu's right edge up with the button's and is placed in the button's parent's coordinates, as the button is still shrunk by its press. A second click on the button closes it: the press closes the menu as one outside it, so `aboutToHide` notes the button when the pointer is on it (`closedBy`, `closedAt`) and the click that follows within a second doesn't reopen it. `placeMenu()` keeps it next to what opened it (`gameMenu.under`, between `underTop` and `underBottom`) once its size is known: below, or above when there's no room, and for the button right-aligned again (`underRight`), since its width is 0 when `popup()` runs. `LATTIS_GAME_MENU=page` opens it from the button (`page/tags`, `page/emulator` with a submenu).

**GameDetails** (`GameDetails.qml`) shows the hero, the action row (Launch and stat chips), the description, tags and Media row (a `TextBlock`, a one-column grid that places each by its index in `General.gamePageSections`, with the same gap between any two), and the side panels (`InfoPanel`, `FriendsPanel`, `AchievementsPanel`, a one-column grid `side` that places each by its index in `General.gamePagePanels`). It goes **compact** when the window is narrower than `details.compact_width`: the stat chips move below Launch, the info panel drops below the description, and the right margin widens. The hero follows the selected game after a short delay so holding an arrow key doesn't decode every image on the way; the rest switches at once, except the description and tags (`textColumn`, a `TextBlock` showing `textGame`), which follow the hero's shown game (`shownHeroGame`) and move with its logo, started by the hero's own switch: as soon as another game is picked, the old content (the description and Show more, and the Tags section unless both games have tags) rises `hero.switch_rise` px away and fades out over `motion.fast` (`textExit`, its own animation on the style's ease-out: on the hero's curve, which reaches the logo's start in a frame or two, it was a cut), while the hero waits and loads; then the new content rises the same distance into place over `motion.normal` (`textIn`, its own animation, started when the hero's new layer begins to arrive, so it settles before the logo does). A game picked while a switch is still in flight (`riseOn` off) only fades: no rise, so holding an arrow key doesn't make the text wobble. One after the other, so they never overlap: drawn over each other, two texts read as doubled. The Description heading, always in the same place, stays on screen between them, so the moment without content doesn't blink; it fades with the content only when one game has no description (`TextBlock.contentOpacity`, `contentShift`, `descriptionHeadingOpacity`). When both games have tags, the Tags section stays through the exit instead (`tagsStay`) and, as the new content comes in, morphs (`tagsMorphing`): the heading glides from its old place to its new one with the new text (`tagsShift`), and the live chips hide (`chipsHidden`) under a Repeater of morph chips over the body, each going from the old chip in its slot to the new one (place, width and color, from `leavingText`'s and `textColumn`'s `tagRepeater`), its name crossfading in place: the old fades out as the new fades in, the two opacities always adding up to 1 (faded one after the other, or with the old gone early, there was a moment with no name, which read as blinking). A chip without a partner moves with the heading, under the others, and fades out in the first half or in during the second. When only one game has tags, the section goes with the content. When the hero switches before the exit has ended, `leavingText`, a second `TextBlock` holding the old game's text, maximum lines, Show more state and the height of its Media row (it loads no clips, `liveMedia` off), finishes it with its own fade (`leavingExit`), so a game picked while the new text is still rising, which restarts `textExit` from where the text is, doesn't bring the old text back. Both are real text; a snapshot of the old read as blurry. So the text waits for the hero (its load delay, and its art up to `hero.switch_timeout`), and while the hero settles, a game picked in the meantime waits with it. Each part can switch without motion on its own: `details.animate_description` (off by default: the description and Show more swap when `textGame` does; on, they fade and rise), `details.animate_tags` (off: no fade, rise, heading glide or chip morph) and, in the hero, `hero.animate_art` (no fade or zoom) and `hero.animate_logo` (no fade-in or rise). For a game picked within `details.rapid_switch` ms of the previous pick (holding or tapping an arrow key) everything skips it: the text takes the selected game at once (`textGame = game`, no exit, rise or fade), and the hero does the same (`Hero.instant`: the new art and logo replace the old with no fade, zoom or rise, still after the art has loaded), and `onShownHeroGameChanged` ignores the hero catching up with an earlier game until it reaches the selection, so the text never goes back. A refresh of the same game and the first game switch without motion. The content's width is computed from the window's width in one expression, with `compactAt()` picking the right margin, rather than from `marginRight`: `compact` starts true while the width is 0, and a binding on `marginRight` would see that old value for a moment, so the hero loaded its first game at the wrong width and then again at the right one.

**The fields** a game's page can show, as chips beside Launch or as rows of the info panel, come from one catalog, **GameFields** (`GameFields.qml`), so a field is added once and works in both places. `GameDetails` makes one for its game and hands it to `InfoPanel`. Its `all` maps each name (`play_time`, `last_played`, `release_date`, `platform`, `status`, `install_size`, `rating`, `times_played`, `first_played`, `recent_play_time`, `date_added`, and the five that carry state of their own: `steam_update`, `steam_family`, `last_backup`, `protondb`, `friends_playing`) to the field's `label`, its `value` as text (`""` when the game has none: no rating, no size; an unplayed game's play time and last played read "None" and "Never" instead, so turning them on always shows them), the chip's `icon`, and what the field does (the Steam entries also give `attention`/`attentionColor` and `iconTint`, which chip and row draw alike, and `hoverTip`; `action` is `url` to open `url`; `GameFields` holds their state, the ProtonDb request and the last-backup load, which run while the entry is in chips or info rows, and `updateAction` comes from the Launch button): `history` (clicking opens play history), `filterPlatform` (clicking shows only that platform), `tip` (the hint for that click), `stars` (the rating, which the info panel draws as stars and the chip puts in its tooltip) and `valueIcon` (the platform's icon beside its value in the info panel too). The three history fields come from `Library.pageHistory()`, read only while one of them is in `[game_page]` chips or info rows, for the shown game only, and again when its play time or last played changes or `historyChanged` names it; a long history arrives a moment later through `pageHistoryReady`, so its chips pop in. The values are kept with the id they were read for and `all` checks it itself: a separate property could still hold the previous game's numbers when `all` runs for the new one, which built the chips, dropped them and brought them back mid-leave, unseen. `recent_play_time` shows the period `General.recentPeriod` names, and its label follows it. Both play time fields are written by `Library.playTime()` from the minutes (`playMinutes`, the history's `recent`) in `General.playTimeFormat`, so changing the format rewrites them in place. `shown(names)` keeps the names that have a value, in their order; both places show only those, in the order `[game_page]` lists them (`General.gamePageChips`, `gamePageInfoRows`). The chips go through a `KeyedListModel` (`chipModel`), scoped to the game: another game's chips replace them at once, while a chip turned on or off, or a Steam chip coming or going on the same game, pops in or out. Each chip is a `Loader`: a field's `StatChip`, or the Steam chip `steam_update` (an update or install), which shows only while there is something to show. A chip pops in with its own animation rather than the Flow's `add` transition: its width settles a moment after the Flow first places it (its `RowLayout` measures on polish), and placing it again cut that transition off, leaving the chip invisible. The one-line action row measures the chips (`statsFlow.lineWidth`) as the sum of whichever are shown.

**Hero** (`Hero.qml`) shows the hero art and logo (or the game's title on a gradient when there's neither). The logo can be adjusted by right-clicking it; its scale, anchor and offsets are saved to the game file (`logo_scale`, `logo_position`, `logo_offset_x`, `logo_offset_y`). Each layer puts the logo's box at its anchor's spot (one of nine: the corners, edges and middle, at `hero.logo_margin` from the sides) plus the offset times the hero's height, and moves it back when the drawn logo (`target`, from its painted size, not the box) would leave the hero; the window shrinking clamps on display without changing the saved offset. What darkens the art behind the logo is the game's own choice, else the theme's: `logo_scrim` is `gradient`, `shadow` or `none`, and when it isn't set the theme's `hero.scrim` (on or off) and `hero.scrim_style` decide, so a game's choice wins over the theme both ways (a gradient shows with `hero.scrim` off, `none` hides it with it on). A gradient (`hero.scrim_color`) goes on the side `logo_scrim_side` names, else `hero.scrim_side`: `top` and `bottom` cover the logo and the margin past it when the logo is on that half (never under 55% of the height), `left` and `right` the same across the width (never under 35%), `full` is a flat dim over the whole hero, and `auto` is the logo's own top or bottom (the whole height, dark at the bottom, for a centered logo). A side away from the logo is the user's choice and isn't corrected. A shadow follows the logo's outline (the title's, without a logo image): a padded `ShaderEffectSource` copy of the logo's box through `MultiEffect`'s shadow in `hero.shadow_color`, `hero.shadow_size` wide and `hero.shadow_offset` down, drawn behind the logo. It is made by a `Loader` only while a layer's style is the shadow, and padded by hand because `MultiEffect`'s own padding doesn't reach outside a `Loader`'s item. Both are drawn by `LogoScrim`, which fills the layer so the logo's box and drawn rectangle are in its own coordinates; each layer passes it its style, side and strength. The art preview in "Look up missing info" uses the same component with the theme's choices and a `shadowScale` for its smaller hero. `logo_scrim_strength` (0 to 2) multiplies the alpha of the gradient's or shadow's color, capped at fully opaque; 0 shows nothing. Each layer works out its own game's style, side and strength, so a switch doesn't jump. With `logoOnly` neither is drawn, and the logo's offset is ignored. With `logoOnly` the offset is ignored and only the anchor's side applies. `pendingScale`, `pendingPosition`, `pendingOffsetX/Y` and `pendingScrimStyle`, `pendingScrimSide` and `pendingScrimStrength` (`"theme"` for the theme's own, `-1` for none) show a choice until the game comes back with it saved; the strength is set live while the menu's slider moves and saved when it's let go. With `logoOnly` (very narrow details), only the logo fills the item — no art behind it. Like the backdrop, it has two layers: a new game loads into the hidden one and fades in (`hero.fade_duration`) once its art and logo have loaded, so the placeholder and the title never flash between games. As it fades in, the art settles from `hero.switch_zoom` to full size and the logo or title rises `hero.switch_rise` pixels and fades in a little later. The old layer stays opaque until the new one has covered it, so while that settles a game picked in the meantime waits, and only the latest is loaded after (holding an arrow key never shows the window background through the art). If the art takes longer than `hero.switch_timeout`, it switches anyway. A refresh of the same game (saving the logo's scale) updates the visible layer in place. Whether the art is the same is decided by `heroArt`, the original, not by `heroUrl`, which becomes the display copy when one is made: the copy arriving for the game on screen keeps the URL it shows until the user leaves that game, with no reload or motion. Before the first game arrives the empty layer shows nothing and doesn't settle, so the first game loads at once. The logo decodes at the hero's decode width whatever its scale: Qt's image reader runs one read at a time, newest first, and can't abort one that has started, so a size that depends on the game made a switch decode the logo twice (the old size, started as soon as the source changed, then the new). `shownGame` is the visible layer's game: it changes when a switch completes, after the art and logo are ready. `logoIn` is its logo's arrival (starting at `logoStart`), so the description and tags in `GameDetails` move with the logo.

**Backdrop** (`Backdrop.qml`) blurs the hero art behind the window. It decodes tiny (`backdrop.decode_size`) and blurs on the GPU; once rendered, each layer is static and costs nothing at idle. Two layers crossfade between games. The fade into the background is a small fragment shader (`shaders/backdropfade.frag`): a smoothstep by default (`backdrop.fade_curve`), since a linear ramp ends with a slope kink that shows as a line over bright art, plus about one 8-bit step of static noise (`backdrop.dither`) so the last few levels near black don't band on high-contrast panels. It follows the hero's shown game (`GameDetails.shownHeroGame`), not the selection, so its read, which costs nearly as much as the hero's own decode, queues behind the hero's and never holds up a switch; it still reads when the backdrop is only hidden by the stats page. With `backdrop.enabled` off `Main.qml` gives it no game, so it reads nothing. When a switch times out (`hero.switch_timeout`) the shown game changes while the hero's art is still loading, so the Backdrop's read can run ahead of the hero's; that only happens with art slow enough to time out.

The window has no system title bar, so the strip above the hero in `GameDetails` is the only area that moves it. It stops short of the window controls (`dragReserve`), so a click just beside a button doesn't start a drag.

## Play history and statistics

Two views show the play history the library keeps (see [library.md](library.md#play-history)).

**LogoAdjuster** (`LogoAdjuster.qml`) is Adjust logo, loaded by `Hero.startAdjust()` the first time it's used (`hero` is its Hero). One mouse area decides on press: the corner handle resizes (the logo grows away from its anchor, up to `maxScale`), the logo moves, anywhere else finishes on release. While moving, the logo's edges snap to the margin lines and its middle to the center lines within `hero.snap_distance` pixels, with a guide (`hero.guide_color`, `hero.guide_width`) for each; Shift moves freely. The offsets are `(drawn position - the anchor's spot) / hero height`, the spot being where the logo is with no offset. On drop (and, debounced 400 ms, after arrow nudges: 1 px, Shift 10) `commit()` re-anchors to the third of the hero holding the logo's middle, recomputes the offsets from that spot so the logo doesn't move, and saves anchor, offsets and, after a resize, scale in one `Library.saveGame()` call. Enter finishes, and so does a click anywhere in `GameDetails` off the hero (`Hero.finishAdjust()`, through a mouse area over the page that takes only that click); Esc puts back the scale, anchor and offsets the mode opened with. `busy` (dragging or a nudge waiting) keeps the Hero from clearing its pending values when an earlier save arrives.

**`AddSessionDialog`** is loaded lazily by `PlayHistoryPopup`, whose Add session button shows when `addableCopies()` finds a copy that isn't a Steam or Proton game. It has a `DateTimeField` each for the start and the end, a `DurationField` for the length and, for linked copies, a Copy choice. `leading` is `"length"` until the end is edited, then `"end"`: the one not edited last is worked out, and a changed start keeps the length and moves the end. `refusal` and `overlap` are worked out from the sessions the popup passes in; the result line shows the refusal, the overlap warning or the session in the popup's words, and `Library.addSession()` checks again. A Heroic copy adds a note. It emits `added(copyId, session)`, and the popup shows "Session added" with an Undo that calls `deleteSession()`. A session with `manual` gets a mark in the Length column (`play_history.manual_mark_color`, tooltip "Added by hand"). The calendar on the date fields is the `[calendar]` section.

**`PlayHistoryPopup`** is one game's history: its totals, then its sessions, newest first. The play time chip (`GameDetails.historyRequested`) and the game menu's "Play history" (the `play_history` action) open it, through `window.openPlayHistory(game)`. It calls `Library.historyFor(id)` each time it opens. A session's right-click menu deletes it with `Library.deleteSession()`, and the toast's Undo (its `link`) calls `restoreSession()`. Ctrl+click and Shift+click select sessions (`selection`, keyed by the session's `end`, as the game list does for games); a Delete selected button over the Close row's free space deletes them all with one Undo (`deleteSessions`), and Esc clears the selection before it closes the popup. Selected rows use `play_history.row_selected`. When the popup closes while an Undo is still showing, `undoHandedOver` passes the Undo to the main window's toast for the rest of its time. The `LATTIS_PLAY_HISTORY=<game id>` hook opens it for a game.

**`OverviewPage`** is the Library overview page (`overview` action, F7; the rail, toolbar and app menu buttons sit above Play statistics). It opens and closes like `StatsPage` (`window.setOverviewOpen()`; opening any of the three pages closes the other two, and `Main.qml`'s `openPage` names the open one), asks for `Library.overview()` when it opens and again when `gamesChanged` fires while it's open, and shows nothing until the first `overviewReady` lands. Like the Gallery it is made ahead: `Main.qml`'s 2 s timer creates it with an asynchronous `Loader` (a click before that finishes it at once) and `warmUp()` asks for the results while it is hidden. Replacing `overview` remakes every card (about 40 ms on the main thread), so the page keeps its results between opens and opens on them: the cards fade in again (`revealed`) and the bars grow again from nothing (`barsGrow`, passed to each card as `regrow`), neither of which remakes anything. The answer asked for on opening is applied only when it changes what the page prints (`keyOf()`, which compares free space as `Library.sizeText()` shows it), and not before the rise ends (`pendingOverview`). It uses the cards shared with `StatsPage` (`Card`, `CardFrame`, `CardTitle`, `CardLabel` and `Muted` in `components/`), wrapped to read their values from `[overview]` (which follows `[stats]` by default), and an `OverviewReveal` fades each card in a little after the one before (`overview.card_stagger`). The columns are three, two below `overview.compact_width` and one below `overview.narrow_width`. Under the tiles and Continue playing the cards are two columns (one on a narrow page), not rows of two: the cards differ in height, and a row leaves a gap under the shorter one. They are children of one plain `Item` (`stacks`) that places them itself, not layouts, because no fixed split stays level as cards come and go with the library. `relayout()` walks the cards in declaration order, puts each visible one in the shorter column (by `implicitHeight`, the same in either column since they are the same width) and stacks it under the card above. Cards above them grow after the first deal (Compatibility as ProtonDB answers come in), which would leave one column far longer if every card kept its first column. So only a card that has been on screen keeps its column (`OverviewReveal.seen`, set while the cards show and the page scrolls, by `markSeen()`), across opens too, until the column count changes (`reset()`), so a refresh doesn't move cards while they are read. The cards below the view are dealt again each time, after the seen ones: dealt in their order, one could land above a seen card and push it down in view. Cards re-place when a card's height or visibility changes. When the columns end less than `overview.column_stretch` apart, the last card of the shorter one grows (`OverviewReveal.stretch` sets `Layout.fillHeight` on its card) so both end level; a bigger difference is left, since a card with a big empty space looks worse than a gap. Declare a new card in `stacks` where it belongs in importance, since the order is the order the cards are dealt. Continue playing's covers share the card's width, each `(width − gaps) / count` wide but between `overview.cover_width` and `overview.cover_max_width`, so a few games don't leave the card mostly empty; more than fit scroll sideways; hovering one shows Play (`playRequested(id)`, which `Main.qml` launches through `Library.gameWithId()`), and clicking it reveals the game in the list (`gameRequested`). The "Play statistics" button emits `statsRequested`. Right-clicking a card opens `OverviewCardMenu` (a `Loader` made on first use): every `OverviewReveal` has a right-button `TapHandler` that emits `menuRequested(position)` (the tiles' grid has its own, Continue playing's reveal is connected in the page), so a click on a bar, game or tag in a card reaches it, as those handle the left button only. `openCardMenu()` works out what applies from what is on screen: a neighbour that is shown (hidden and empty cards are skipped) for Move up and Move down, which swap the two in the column's list (in one column, in the left list followed by the right one), the other column only with two columns, and for the tiles and Continue playing Move below / above the cards, which puts them next to the columns. Before the first column change `fixColumns()` writes both columns as the screen shows them (`stacks.currentLists()`; one column puts every card in the left list, the one place the cards stay as they are), so the dealing stops moving anything; Hide does the same first, so the cards left don't shift. Moving to the other column puts the card at the height it was at (`stacks.slotIn()`). The menu returns focus to the page when it closes, so the keys keep scrolling. `General.setOverview*()` write the choices, and a write the file refuses is shown as a toast through `message`. `LATTIS_OVERVIEW=1` opens it for a screenshot.

**Edit mode.** `Customize` in the title row (or `Customize overview` at the end of a card's menu) sets `OverviewPage.editing`; `Reset layout` and `Done` take its place, and Escape leaves it (a drag in progress first). While it's on, every card shows: `OverviewReveal.visible` is `editing || (has && !hiddenCard)`, where the page gives each card `has` (whether its data has anything) and `hiddenCard` comes from `General.overviewHidden`; a card with nothing to show prints its `title` over "Nothing to show now" in its place (`overview.edit_placeholder`), and a hidden one stays where it is at `overview.edit_hidden_opacity`. `OverviewEditFrame` is laid over each card (in `OverviewReveal`, and over the tiles' row): a `MouseArea` that takes every click and hover so the card underneath gets none, a grip at the top left (a `DragGrip`, left out in a one-column window, where nothing is dragged) and an eye at the top right, both straddling the card's top edge, clear of its title (`overview.edit_button_*`, `edit_icon*`). Both are found by their `text` ("Move Storage", "Hide Storage"), which the UI driver needs. The eye is `toggleHidden()`: showing is `setOverviewHidden()`, hiding is the menu's `hideCard()`. A card in a column is dragged through `stacks`: `startDrag()` takes the lists as they are on screen (`currentLists()`), `moveDrag()` moves the card with the pointer and, whenever the slot its center is over changes, puts it in that slot of a `preview` copy of the lists and calls `relayout()`, which deals the others by the preview (they ease to their places, `OverviewReveal`'s `Behavior`s on `x` and `y`, off for the card under the pointer: `dragged`) and leaves the dragged card's own position alone. The slot is judged against the other cards where they are without the dragged one, so a card sliding aside can't flip it back. `endDrag()` writes the preview with `setOverviewColumns()` if it differs from the lists the drag began with (so a drag that ends where it began doesn't turn off automatic dealing) and the card settles in from where it was let go. The tiles and Continue playing drag in the page itself (`rowDragStart()` … `finishRowDrag()`): the row follows the pointer through a `Translate` and a line (`overview.edit_drop_indicator`) shows where it would land among the other rows and the two columns together (`stacks` counts as one), without the others sliding, since a `GridLayout` can't ease its children; on a drop it settles to that place and `setOverviewRows()` writes it. A drag held within `scrollEdge` of the view's top or bottom scrolls it (`autoScroll()`, as in `DragReorder`). `Reset layout` is `resetOverviewLayout()` and `stacks.reset()`, which forgets the columns the cards were in, so the automatic dealing starts again.

The page's cards are their own files, so `OverviewPage.qml` only deals them out: `OverviewCard`, `OverviewCardTitle` and `OverviewQuiet` are the shared cards wrapped to read `[overview]`, `OverviewReveal` fades a card in (`order`, `shown`), and `OverviewStorage` is the Storage card. Storage draws a bar per drive from `overview.drives`: a segment per platform in the platform's color (its `color` from `platforms.toml`, which `defaultPlatformColor()` fills in for built-in ids, else `overview.platform_colors` by the platform's place in `overview.platformList`, so a color doesn't move when rows sort differently), largest first, then Other, over the free-space track. A platform under `overview.storage_fold_percent` of the drive is folded into Other with the drive's non-game files, and Other is left out when it is under that share and nothing was folded. Each drive has its own legend under its bar, in the bar's order; hovering a segment or a legend entry replaces the drive's "N free of total" with that part's square in its color, its name, its size in bold and its share; Other also lists the platforms folded into it in a tooltip. Drive and legend sizes are rounded to whole units (`Library.sizeText(bytes, 0)`). The bars grow once when the page opens (`barsGrown` keeps a refresh from growing them again). Largest games sits under the bars, because the card sits in a half-width column. A row is the outlined cover (`overview.storage_cover_outline`), the title and size on one line, the platform and "Played …" on the next, and a thin bar of its size against the largest row (`overview.storage_size_bar_height`); a click on it emits `gameRequested`. **Show all games by size**, at the right of the Largest games heading, emits `allBySizeRequested`, which `Main.qml` answers by clearing the filters, showing installed games only, sorting by size, largest first, and closing the page. There is no Uninstall on the rows: the page only shows the library, and the game's own page and menu uninstall it. The card is hidden when there is no drive and no installed game to list. The breakdown cards are `OverviewPlatforms` (Games by platform), `OverviewStatuses` and `OverviewYears`, built from `OverviewBarRow` (a name with an optional quieter `detailText` under it, a bar and a count, hovered and clickable; the count column is `overview.count_width` wide in every card, so bars in stacked cards end in one line, and a card whose longest count is wider widens it; Games by platform keeps "N installed" in the detail line; Games by platform and Status draw each bar as the entry's share of the library, as Play statistics does, and add the percentage to the count; `grown` and `grew()` keep a refresh from growing the bars again, as in Storage). `OverviewTags` (Top tags) is the odd one out: it wraps `OverviewTagChip`s (a `TagChip` in the tag's own color, found by name in `Library.tags`, as the filter panel draws it; `Theme.overview.tag*`) in a `JustifiedFlow` of `tag_rows` (3) rows under a "Click to filter" hint, and a click emits `filterRequested(tag)`. `OverviewPlatformInfo` holds the platform list and gives a platform its color and name, so Storage and Games by platform show the same one. **`StatsPage`** is the Play statistics page. It covers the rail, the list and the details; only the toolbar, the toast and the window controls stay above it. `Main.qml` loads it on first use (`window.setStatsOpen()`), and the `play_statistics` action (F9, the rail's bar chart button, the toolbar's button) toggles it. It asks for one period with `Library.monthStats(year, month)` or `Library.yearStats(year)` and shows the answer when `monthStatsReady` or `yearStatsReady` delivers it, ignoring an answer for a period or mode it has left, so stepping quickly never shows a stale one. Going from Year back to Month keeps `monthYear`, the year the month belonged to, and falls back to that year's last pickable month when the year changed. `start()` always opens on the current month. Left and Right step the month, or the year in year mode (`step()`, bounded by `canPrevious` and `canNext`), `pick(y, m)` and `pickYear(y)` jump, Esc and "Back to games" emit `closeRequested`, and a click on a Most played row emits `gameRequested(id)`, which selects the game and leaves the page. The page's own pieces (`Card`, `Highlight`, `Share`…; the Back to games button is `ChromeButton`, shared with the Gallery) are inline components in the file. The year view's Hours by month and Hours by weekday cards are `Component`s in `Loader`s, made the first time the year view is used. Hours by month takes its chart height from the day chart's card, so the cards below don't move when the mode changes.

The page fades in and out over the views (`Main.qml` keeps them drawn until it covers them, `statsCovering`) as one layer, so the cards don't fade separately over the background, its content rising `stats.page_offset` px as it opens and sinking back as it closes (`leave()`). The fade-out waits until the content has mostly sunk; a mirrored close (the reversed curve) would save the movement for when the page has all but faded, where it can't be seen. The bars grow from the baseline when the page opens and move to the new hours when the period changes: the day, week, month, weekday and strip charts repeat a fixed count of columns (31, 6, 12, 7, the strip's length) and read their period's entry by index, since an array model would rebuild the columns on every change and there would be nothing to animate from. Each column animates its share of the chart's height, not its height, so a resize doesn't animate. `start()` sets `resetting` while it clears `stats`, so the bars drop to nothing at once and every open grows them again. A new period lands as soon as it arrives (`land()`). Text that changes crossfades: a `FadeLabel` keeps two labels that take turns (`Turns`), the new text fading in on the hidden one as the old fades out in place, so there's never a moment with neither; the row icons do the same. The labels read `shownYear`/`shownMonth`, the period on screen, not the picked one, so they change once, with the data. `fading` turns the crossfade off for the first period after opening, which has nothing to fade from. The tile values count to the new numbers instead (`tileValue()`). The rest is kept rather than rebuilt, in fixed slots: the day columns, day labels and week lines narrow or widen as the month length eases (`dayCount`), the week lines slide and stretch to their new days, the Hours by week columns follow the week count, and the scale's gridlines and labels (`GridLines`, `TickLabels`) move to the new ticks. The chart tips fade, and glide on a spring from column to column; `tipIndex` keeps a tip's column while it fades out.

Switching between month and year swaps what differs: Hours by day for Hours by month, Hours by week for Hours by weekday, and the month strip for the year strip. Each view's own cards read the last period that landed in that view (`monthStats`, `yearStats`), not `stats`, so the view on its way out keeps its period while it fades. The two views crossfade (`yearness`, eased, gives `monthPresence` and `yearPresence`), and their bars are scaled by their view's presence as well as faded, so the outgoing bars sink to the baseline as the incoming ones grow instead of two full charts standing over each other. Fading one view out before the other in would leave the card empty halfway, which shows as a flash. Each pair of cards sits on one `CardFrame` that stays, its two `Card`s unframed (`framed: false`), since two crossfading frames would let the background show through halfway. The incoming view starts from nothing, as on opening: `land()` clears its copy under `resetting` first, so its bars grow from the baseline and the rest lands in place. The cards both views share (the tiles, Hours by platform, Most played, the highlights) move to the new period as they do between months. The title button keeps one width for months and years, so switching doesn't move the arrows; a longer month name glides to its width.

**`GalleryPage`** is the Gallery: every clip and screenshot the library has, as one grid. It is loaded and covers the rail, list and details like `StatsPage` (`window.setGalleryOpen()`, the `gallery` action, F8, the rail, toolbar and app menu buttons; opening one page closes the other), with the same rise and sink (`gallery.page_offset`). `start(gameId)` resets the filters (with a game id, the Game filter starts on that game: the Media row's "Show all") and calls `Library.allMedia()`; with **warm results** (`warm`: a finished search the page still holds, from the hidden search `Main.qml`'s preload timer starts through `warmUp()` or from the last opening) it keeps `all`, `games`, `rows` and the lists and shows them at once, then searches again quietly (`quiet`, results collected in `pending`) and `applyFresh()` replaces the items only when their `keyOf()` keys differ, keeping the top item in place. `checkWarm()` (on `Library.gamesChanged`) searches again if the page is open, or drops the warm results if it is hidden, when a game they name has left the library. Without warm results (opened before the preload, or it failed) it clears everything first. Every `allMediaReady` batch is added to `all` (`take()` asks `Library.mediaGames(ids)` for the games it hasn't seen yet, keeping each in `games`, or null for one the library doesn't show, whose items are dropped), and a 150 ms timer, started by the first batch and not pushed back by the next, lays them out together, so the grid fills as they come, with "Looking for more…" in the header until the batch with `done`. The header counts the items shown ("48 items", or "12 of 48 items" while a filter is on), and its tile size control is a pill shaped like the header buttons: − and + (`gallery.slider_step` narrower or wider) around a slim `SettingsSlider` (`handleSize`, `trackHeight` and `fillColor` set from `gallery.slider_*`). `rebuild()` sorts `all` into `shown` (the list the viewer steps through, newest or oldest first as `General.gallerySort` says), and `relayout()` turns it into `rows` for a `ListView`: a group heading (`{header, key}`, its label, icon and count in `groupInfo`) or a row of tiles holding as many as fit (`columns`, from the tile width the slider or `[gallery] tile_width` asks for; the tiles are widened so each row fills the width). Only the visible rows have delegates, so only their tiles decode their pictures. A `ListView` section would need a role per row, which a JS array doesn't give, so the heading that sticks to the top is a separate overlay (`topRow`, `headerOfRow`) over the list, which the next group's card pushes up out of the way. When grouped, each group sits in a card (`gallery.group_card_*`, `group_padding`, `group_radius`, `group_spacing` between cards); since the rows are separate delegates, each draws its band of the card (`CardSlice`: the whole rounded card clipped to the row, so only the heading row and the group's last row (`last` in `rows`) show its edges). The grid's scroll bar sits in the right margin, outside the cards, and isn't attached to the list: every row's height is known (`rowSpan()`, summed into `rowTops` and `contentTotal`), so the bar maps its position to an exact offset (`exactY()`, `scrollToY()`) instead of the `ListView`'s `contentHeight`, an estimate from the rows made so far that shifted while scrolling and made a drag jerk the grid. The grouping (Month, Game, None), sort and tile size are `General.galleryGroup`, `gallerySort` and `galleryTileWidth`; the slider and the − and + buttons write the width 400 ms after the last change. A change of columns keeps the item at the top in place (`anchorKey()`).

The filter lists and the sidebar's five sections wait for `listsReady` (`buildLists()` sets it, a cold `start()` clears it), so on a cold open the sections unfold (`Unfold`) when the lists arrive instead of jumping, and "No game by that name has media" shows only after that.

## The game editor

`GameEditor.qml` is both the game settings dialog (opening a game) and the "+" flow (adding a new one). It opens as a dialog over the main window, created on first use. It handles four game kinds, each with a different set of fields.

A game's Properties is four tabs behind a rail on the dialog's left (`tab`, `tabs`): 0 General, 1 Images, 2 Launch, 3 Saves ("Saves & mods" while `managerGame`). Each tab is its own file, `EditorGeneralPage`, `EditorImagesPage`, `EditorLaunchPage` and `EditorSavesPage`, built from `EditorCard`, `EditorField`, `EditorHint`, `EditorTextAction` and `EditorMediaFolderRow`. `GameEditor` keeps the state (`game`, `pick`, `new*`, `changes()`, `save()`) and the pages expose their controls as `property alias`, which `show()`, `changes()` and `save()` read by id; so every page is instantiated and shown by `visible` (`pageShown(n)`), in the one `ScrollView`, and the editor stays behind `editorLoader`. The dialog is `game_editor.width` by `game_editor.height` (capped by `max_height`) so a tab switch doesn't resize it; switching is instant. `openFor(id, tabIndex)` takes an optional tab (General by default, nothing remembered); `openMediaFolders()` and `browseArt(kind)` switch to Images first. `save()` switches to the tab of the field in error before focusing it. `changeTabs` maps `changes()`'s keys to tabs, and with `artEditor`, `tagsEditor` and `managerLinks` decides which rail items show the unsaved dot (`changed_dot`). Ctrl+Tab and Ctrl+Shift+Tab (`stepTab()`) go through the tabs, and the rail takes focus with Up and Down. Adding a game (`adding`) has no rail: the General and Launch pages show together.

The kinds:

- **ROM games**: ROM path, platform, emulator, launch arguments.
- **Steam games**: launch options, Proton version — both saved to the game file and written into Steam's files; play time and last played are Steam's, shown read-only.
- **Proton games**: a Steam shortcut (kept in step with the game file), plus a program, start folder and install folder.
- **Linux games**: a program the launcher runs directly; play time is recorded by the launcher.

The `pick` object (from `Library.inspectRom()`) drives the "+" flow: it names the platforms the file matches, whether it's a Windows or Linux program, and what the title is. On Save, only the keys that changed from the game's current values are written in one call to `Library.saveGame()`. Cancel and Escape discard everything, including art downloads and tag changes.

Every game has a **Save locations** section in the Saves card, under the backups for a game with backups. `EditorField`'s `heading` and `actions` make it a section heading with an **Add** action (the folder picker's `saves` target). Under it come the game's own locations (`savePathsShown`: `newSavePaths` once edited, else `savePaths` from `gameForEditing()`, kept with `~` through `homeTilde()`; each row has ✕), then the match row and the found ones (`saves.paths` without those inside an own location, the first three shown and the rest in an `Unfold` behind a "more" button). Save writes `save_paths` (or removes it) and removes the older `save_folder`.

A game with backups (`backupGame`) has a **Backup options** card under Saves, its rows (`OptionRow`, inline in `EditorSavesPage`) laid out like the Settings window's: the label at the left, the control at the right edge, and a hover highlight that reaches `game_editor.option_row_bleed` into the card's padding. **This game has no saves** (`noSavesSwitch`, written as `no_saves`; its label toggles it too) first, then **Backup when the game closes** (`autoBackupBox`, `auto_backup`), which crossfades in place with a note saying what the switch does while it is on (only the card's bottom edge moves). `SavesPanel`'s `noSaves` follows the switch: its empty state reads "No saves to back up", and the match and folder buttons fade out without giving up their room, the text sliding to the middle, so the Saves card keeps its height and the switch below never moves under the pointer.

Every game (`mediaGame`, not while adding) has a **Media folders** card under Images on the Images tab. Its field is a summary ("Steam's", "Emulator's" for a ROM game, "Steam's + 2 folders", "None", "2 folders"); the Edit button opens a popup (`game_editor.media_popup_width`) under it, anchored to the button's right edge: Steam's clips and screenshots as a fixed first row with the Steam icon and an open button (`Library.showSteamMediaFolder()`; Steam games and Proton games in Steam only), one `MediaFolderRow` per folder (mono path elided in the middle, open, ✕), a divider (only when something is listed above it) and **Add folder** (`folderPicker`, target `media`; a folder already listed isn't added twice). A folder `GameRunner.folderExists()` doesn't find is dimmed (`game_editor.read_only_opacity`) with "Not found", and its open button is off. The edits are held in `newMediaFolders` (null means unchanged) and written with the rest on Save as `media_folders`; Cancel drops them. `LATTIS_MEDIA_FOLDERS=1` opens the popup for screenshots.

Steam, Proton and Linux games get a **Mod managers** card below Saves on the Saves tab (`managerGame`): the managers linked to the game (name, Native or Proton, ✕ to unlink), **Link** (a `ModManagerMenu` of the managers not linked yet) and **Add** (`addModManagerRequested(gameId)`, which Main answers with `ModManagerDialog` and the game pre-linked, saved on its own). Links and unlinks are staged in `managerLinks` and written with Save, through `Library.setModManagerValue(id, "games", ids)`.

The game page's **`mod_manager` button** (GameDetails `managers`, from `Library.modManagers`) shows only while the game has a manager. With one, a click emits `modManagerRequested(id)` and the tooltip is "Open <name>" ("<name> is running" while it runs); with several the tooltip is "Mod managers" and a click opens `ModManagerMenu` under the button. A dot (the badge) shows while any of them runs (`GameRunner.runningManagers`). The `open_mod_manager` action does the same through `GameDetails.activate("mod_manager")`. **GameMenu** (the right-click and ⋯ menu) lists "Open <name>" per manager after Open save folder, and "Add a mod manager" for Steam, Proton and Linux games (`managerChosen(id)`, or `chosen("add_mod_manager")`). Main's `openModManager(id)` is where every route ends: it shows "Run <game> once first, so Proton creates its prefix" with a Launch button when `GameRunner.missingPrefixGame()` names a game, else calls `GameRunner.launchModManager()`; `addModManager(gameId)` loads `ModManagerDialog` lazily.

The form makes room for its scroll bar while the bar shows, and keeps that room (`form.scrollRoom`) until the editor opens another game: content that only overflows at the narrower width would otherwise hide the bar, widen, fit and show it again without end, which hangs the window.

The editor tracks `steamPending` (edits waiting for Steam to close) and `steamEdited` (edits changed but not yet saved). When saving would queue changes for Steam, it says so and lets the user save first to avoid a second visit.

The lookup, art browser, and detailed lookup live in the editor's own sub-views (`LookupRow`, `ArtBrowser`, `DetailedLookup`), created on first use. Nothing is saved until the editor's own Save.

## Metadata lookups

**`LookupRow.qml`** is the thin bar under the game editor's title field. It transitions between four states — `running`, `matched`, `pick` (a list of candidates), and `hint` — as the lookup progresses. "Not this game?" triggers a re-search; "Undo" puts the fields back.

**`DetailedLookup.qml`** searches IGDB for any name on a chosen platform and lists up to 50 results with their details. It is shared by the game editor and BulkLookup (for a game not found automatically). The `chosen` signal gives the selected candidate and the name searched back to the editor, which applies it as it would any automatic match.

**`ArtBrowser.qml`** shows SteamGridDB's art for a game, one tab per kind, plus a Steam tab. In the editor, "Use selected" downloads the picks (a local Steam file is handed over as is) and hands them to the editor as local files; nothing is saved until the editor's Save. In BulkLookup (`bulk: true`), picks are kept in the results rather than downloaded immediately; Apply downloads them all. "Other game" swaps the grid for a search (`searchArtGames`, run 300 ms after typing stops, the last text and results kept until the popup closes or `showStep` moves on); `showGame(id, title)` loads another game's art by resetting the tabs but not `picks`, while `openFor` resets everything. `ownId`/`ownTitle` are the game the browser was opened for, and `other` is true while another game is shown. `openWithoutGame(title, kind)` (the editor, when `findArt` finds no match) opens straight into the search with `noGame` set: no grid or "Back to", Escape closes the popup, the ✕ clears the text, and picking a game emits `gamePicked(steamGridDbId)`, which the editor stores in `lookupIds.steamgriddb`.

The **Steam tab** (`id: "steam"`, after Icon) shows Steam's own cover, hero and logo in one row (`steamImages`, limited to `shownKinds`). `openFor` and `openWithoutGame` take the Steam app id last (`steamApp`: a Steam game's own id from `Library.steamAppFor`; 0 looks it up when the tab opens). `loadSteam()` first reads `Library.steamLocalArt(steamApp)` (Steam's grid folder and library cache, as file URLs) and skips the network when every kind is there; otherwise it calls `Metadata.steamArt` and keeps the local files over the web images, or `Metadata.findSteamApp(ownTitle)` first when there is no id; a found id is emitted as `steamAppFound(appId)` (the editor saves it in `lookupIds.steam`; bulk mode keeps it on the step and `BulkLookup::setSteamApp` saves it on Apply). Steam picks are `{id: url, steam: true}` and share `toggle(image, kind)` with the kind tabs, so a pick shows on both tabs. A logo that fails to load is dropped (`dropSteamImage`). "Other game" doesn't touch the tab. States: loading, no game on Steam, no library art, or the error.

**`BulkLookup.qml`** runs in two stages: choosing the games to look up (filtered, checked), then reviewing the results and choosing what to apply. Nothing is written before Apply. The `forTags` mode lists every game and proposes tags that fit the IGDB match. `reviewing` switches the stages.

Both stages share one layout: a title row, a sidebar `game_editor.bulk_sidebar_width` wide with the list beside it, and a bottom bar under a line. The sidebar is a card (`SideCard`: `game_editor.card_background`, `radius.large`, `layout.border_width`) that scrolls its contents on its own with a `SettingsScrollBar`; the list's rows leave `scrollGap` free so a row's highlight never runs under the bar. Its sections are `SideSection`s (an inline component: a caps heading with a chevron that folds the section, kept only while the window is open), `BulkOption` rows and `TextLink`s. A `BulkOption` is a checkbox, or with `radio` a radio button, or with `showDot` a round dot in the color `dot` (a result state), or a `swatch` (a tag's color), then the label and a `count`; the radio's ring uses `game_editor.bulk_radio_border_width`, not the input border, since a style can set that to 0. The two stages are `ScreenSwap`s in one `Item`: going to the results slides the list screen up and out while the results slide up into place (`settings_window.page_offset`, `motion.normal`, linear fades at half that, like Settings pages), and back down the other way; a result row's pick, error, not-on-IGDB and apply-error panels are one `Unfold` that folds with the chevron; `BulkOption` rows and the window's check boxes fade between states and pop their check marks and radio dots (`MarkPop`).

- **Choosing:** the sidebar has a `SegmentedToggle` (Missing info | All games, bound to `includeComplete`), the Missing (or, with `replaceExisting`, Look for) checkboxes, the Platform radios, the tags button with the checked tags under it, and the not-on-IGDB row; Clear filters is pinned under the scrolling part. Counts come from the model (`missingCounts`, `platforms[].count`, `tagCounts`, `notOnIgdbCount`). The tags button opens `BulkTagsPopup`, a `MotionPopup` inside the window (not a window of its own) that filters `allTags` by the typed text. The list has a header with a tri-state checkbox that checks or unchecks every listed game, and a chip per missing field in each row; chips of categories unchecked in the sidebar are dimmed.
- **Reviewing:** the sidebar has the progress pill, the state rows (`stateCounts`, which set `resultFilter`) and the actions for every match. Every result is a card; a matched one with details open has a darker tray hanging under the row, holding the match column (the cover, `coverLarge`, shrinks with the window; 24% of the tray's width, at most `bulk_match_cover_width`) and the Info, Tags and Art `SectionCard`s. The Art section is a `Loader` that picks its layout by whether the match column is shown (a matched result): `ArtGrid` beside it, `ArtPreview` otherwise. `ArtGrid` is a `GridLayout` of `ArtCell`s in Properties' arrangement (the hero, the logo and icon under it, the cover spanning both rows); the hero's height is solved from the card's width so hero, gap and cover fill it, capped by `bulk_art_height`, and the small row is 0.82 of it. Each cell has its `ArtCheck` above its picture; a header wider than the picture is elided to its width, with the full text in a tooltip. `ArtPreview` (art-only results, which have the full width) puts the hero with the logo and icon on it and the cover beside, sized so the two fill the card's width at the theme's hero aspect, up to `bulk_art_height` tall, with the checks as one row under it. Its logo is placed as `Hero` places it at the theme's defaults (no per-game scale or offset: the game's own may be about to change), with a `LogoScrim` behind it whose shadow is scaled by the preview's height over `hero.max_height`. Both share the helpers on `root`: `artSource(r, kind)` is the suggestion when there is one (checked or not), and the game's own picture, from the result's `ownArt` (kind → URL, from `LookupGame::artUrls`), only for a kind the lookup leaves alone; `artUnchecked(e)` and `artDim(e)` say which suggestions are shown with `UncheckedGray` (a `MultiEffect` with `bulk_art_unchecked_saturation`; on the preview's logo and icon it also darkens, as fading would let the hero show through) and at `bulk_art_unchecked_opacity`. Each found piece is an `ArtPick` (hover overlay, click opens the art browser on its kind). An art-only result (Not found with art) opens with a banner at the top of its tray (an info icon, the "IGDB didn't find it" text, **Detailed lookup** and **Not on IGDB**, tinted by `bulk_banner_*`), so its header stays one line; a Not found result without art keeps that row in the header.
- **Folding:** a row folds with its chevron or a click anywhere on it. Which rows are folded is kept by game id in `collapsed`, not on the delegates, since the list recycles them; it is cleared when a lookup starts.
- **Pictures:** `ArtThumb` draws the picture as a `Shape` whose fill is the picture itself (`fillItem`), not through a masked layer: a layer could be drawn once before the picture was ready and stay blank. The fill transform scales and centers it (crop or fit), and a fitted picture that doesn't reach the corners keeps square ones.

## Setup guide

`SetupGuide.qml` overlays the main window from the first start of a new library, and is also openable from the app menu. It shows one centered card with a step bar and the current step's page. The card's scale is 1 on 1080p screens or smaller, and grows toward `onboarding.large_screen_scale` on larger ones. The window moves only by dragging the strip along the top (short of the window controls, by `dragReserve`, which `Main.qml` sets). Clicking a step in the step bar jumps to it, except Done, which only Look's Finish reaches.

Each step page is a QML file in `qml/setup/`, loaded on first visit and kept so Back returns to what was typed. Pages can override the card's title and description, add a `headerAction` component under the description, change `nextText`, and handle Next themselves by returning `true` from `next()`.

The Steam step holds imports while the setup runs: shortcuts picked wait in the guide's `shortcutsToAdd` until Finish, so they're added in the same batch as the scan-triggered lookups. The Heroic step's switches are the `[heroic]` settings, and the scan holds its merge back until Finish, so while `Library.setupPending` the page counts the scan (`scanInstalled`, `scanOwned`) rather than the library. The Look step applies a theme immediately on each pick; the guide itself reflects the change. Finish starts the scans and ends the guide.

Every step gets a card `onboarding.card_height` tall (the Game info step's size; a taller step scrolls, and a short window shrinks it), its bottom edge fixed so the buttons stay put between steps. The guide opens after the first frame (`ready`, set after `Component.onCompleted`): the card grows in like a popup over a fading backdrop. Closing goes through `dismiss()`, which plays the exit and emits `closed` when it ends, so `Main.qml` unloads the `Loader` after it; with Reduce motion it emits at once. Each page sits in a slot; changing step slides the old page out and the new one in (the direction is `direction`, set by `goTo`), the old one taking no room.

`SetupBackdrop.qml` is the base color (`onboarding.background`) with `SetupCoverWall.qml` loaded over it, tinted by `onboarding.backdrop_tint` (the theme's background) at `backdrop_dim` with a `backdrop_vignette` toward the edges, and passes its `active` on to the wall (paused rather than stopped while false, so the rows keep their place). The cover wall's look (tilt, covers' size, speed) is fixed in `SetupCoverWall.qml`, not a theme setting; its `moving`, `tint` (default `onboarding.background`), `dim` and `vignette` are properties, which `SetupWelcome.qml` sets from `onboarding.welcome_art_*` for the second, darker, still wall in its panel. Only that wall is rounded with a `MultiEffect` mask; the logo, tagline and screenshot sit outside the layer in a plain clip, because a layer under the card's `scale` is drawn at the unscaled size and stretched blurry on a 1440p screen. The screenshot (`resources/setup/welcome.webp`) goes through `coverround.frag` for its corners. The guide passes its `cardScale` in as `renderScale`, and the wordmark (`Wordmark.pixelScale`) and the screenshot are decoded at that size. The screenshot is also sized and placed on whole device pixels (re-aligned on the window's `afterAnimating`, since nothing signals a change of scene position), so it is drawn 1:1 rather than resampled at the card's fractional offset. It lays 44 bundled Steam covers (`resources/covers/<app id>.webp`) out flat in rows that move in alternating directions (one set of covers per row; a cover leaving on one side comes back on the other), draws that into a texture, and `qml/shaders/coverwall.frag` tilts it per pixel by inverting the perspective projection, with the wall sized to the part of the plane the window shows. Qt's own 3D `Matrix4x4` transform on the individual covers dropped the ones on the near side. `qml/shaders/coverround.frag` rounds each cover's corners. The rows stop when `onboarding.backdropMotion` is false or Reduce motion is on. Their speed is the wall's own literal, passed through `Motion.duration()`, so `duration_scale` scales it.

## Settings window

`SettingsWindow.qml` is a category sidebar with a scrollable content area. Categories are declared in `categories` (a constant list of `{key, title, icon, page, sections}`); `showCategory(key, item)` opens one. Each page is a `PageLoader` that loads when first shown; once the window is visible, a timer loads the pages not yet opened, one every 120 ms, so the first click on a heavy page (Emulators, Platforms) is instant. Closing the window unloads them again (`visited` back to false for all but the open page) and, half a second later once the Loaders have deleted them, `WindowState.releaseMemory()` hands the memory back; reopening loads them again. Switching category moves along the sidebar's axis over `motion.normal`: going down, the old page slides `settings_window.page_offset` px up while the new one rises the same distance into its place; going up reverses both. Both fades run together over the first half, linearly, so the two opacities always add up to 1: staggered, there were frames with both pages nearly gone, which read as a blink. Each page has its own description label above, whose opacity follows its page's, so the descriptions crossfade with the pages. The window drives it (`onCurrentCategoryChanged` calls the loaders' `leave()` and `enter(direction)`), not each loader's `current`, so the direction is known before either page reacts. The sidebar shows section links under the active category; the link for the section currently scrolled to is marked.

Each page provides `currentSection` (name of the topmost visible section), `jumpTo(section)`, `jumpBy(step)`, and `focusSearch()`. The sidebar uses these to scroll and highlight. On the Customize and Keyboard pages `jumpTo` switches section the way the window switches category (`SectionJump`): it grabs the list into an image (`grabToImage`, so it costs nothing while idle), waits until that image can be drawn (jumping before leaves a frame with neither view), jumps the list there at once, then slides the snapshot away and fades it out while the rows (the list's `contentItem`, so they stay clipped) slide into its place and fade in. It uses the same timing as the category switch. The snapshot leaves out the scroll bar strip; the real bar stays and its handle glides to its new place (`SettingsScrollBar.glide()`), since a faded copy over it brightened the track. The page ignores scrolling meanwhile, so the sidebar keeps the section jumped to. `swap(changeRows, direction)` runs the same slide around any other change to the rows: the Changed only and Show filters on Customize use it, sliding like going down when they narrow the list and like going up when they widen it. Pages also have `clearSearch()` for the Escape chain: Escape steps out of the focused field, then clears the page's search, then closes the window.

Escape is handled at the window level, not inside each page, so it behaves consistently. Clicking empty space unfocuses the active field (same as the first Escape), via `isEmptySpace()`.

The General, Game page, Library, Steam, Mod managers, Platforms, Emulators, Metadata, Appearance, Customize and Keyboard pages each own their section.

**Game page** (`GamePage`) is what the game's page shows, the `[game_page]` settings of `General`: a card each for the chips, the buttons, the panels and the info panel rows (`GamePageList`), then a Play time card with the format and the Recent play time period (two dropdowns; the format's choices are written with the selected game's play time, or 863 minutes without one) and the Show the description and Show tags switches. A list has a row for every choice of its place, hidden ones included, in `General.gamePageOrder(place)`: a grip, the icon, the name, a hint and a switch (`setGamePageShown()`). A hidden entry's icon and name fade to `settings_window.off_entry_opacity`. The hints give the selected game's value when it has one (the window's `game`, which `Main.qml` binds to the list's current game, read through a `GameFields` of the page's own that always reads the play history, so the history fields have examples too), and what the entry is otherwise; the Steam chips' hints say where their information still shows when they're hidden. The rows only rebuild when the order changes, so a switch flips in place. Changes apply as they're made: the game page listens to `General.gamePageChanged`. Its search filters the rows by name and hint (the period and switches by their names), and dragging waits for it to be cleared. Its Problems button shows `General.gamePageProblems`. A List view | Grid view `SegmentedToggle` beside the search chooses whose lists the page edits (`gridLists`; it opens on the view in use and isn't saved): the Chips and Panels lists switch to `grid_chips` and `grid_panels` (the Grid view's panels also list Tags), and the Buttons and the description, tags and media lists, which the side panel has no use for, are hidden; the info rows, the Friends groups and the play time settings are shared.

**Right-click menus on the page.** Right-clicking the chip row (including the empty space right of it, beside Launch, so it works with no chips shown), a button of the action row or the info panel opens `GamePageMenu` (`place`: `chips`, `buttons` or `info_rows`, and the Grid view's `grid_chips` and `grid_panels`, opened from `GridPanel`) at the pointer, through `GameDetails.openPageMenu()`; a `TapHandler` for the right button on each, so a chip's own left click is unchanged. It is created on first use. It has a check row for every choice of its place in `General.gamePageOrder(place)` (a `SettingsMenuItem` with `keepOpen`, so a toggle writes `setGamePageShown()` and leaves the menu open; the rows are rebuilt only when the order changes), then "Customize game page", which Main turns into `openSettingsAt("game_page")`. In the chips' and the info panel's menu, `recent_play_time` is a submenu (inserted with `insertMenu()`, since a submenu isn't an Item) holding the four periods (`setRecentPeriod()`); the entry itself still toggles the field. The names come from `GamePageNames`, which the settings page uses too. Reordering is on the settings page only. `LATTIS_GAME_PAGE_MENU=<chips|buttons|info_rows>[/period]` opens it.

**Dragging rows to reorder them** is shared by the Platforms and Game pages. `DragGrip` is the handle: a grip icon with a `MouseArea` that starts a drag past the start distance and reports `dragStarted`, `dragMoved` and `dragEnded(dropped)` in its own coordinates (`area`); `color`, `hoverColor` and `iconSize` restyle it (the Library overview's edit mode does). `DragReorder`, placed in the card beside the rows' column, keeps the drag (`from`, `to`, `dy`), draws the drop line, and gives each row its offset (`offsetOf(index)`; the row under the pointer follows it, `follows(index)`, while the others slide aside and ease) and `isDragged(index)` for the dragged row's opacity and z. It needs the column, the `Repeater` and the rows' `ids`; only the first `count` rows take part. Given the page's `flickable`, a drag held within `scrollEdge` of its top or bottom scrolls it, faster nearer the edge and never past the card's end; the pointer is kept in scene coordinates so the row's place is worked out again as the page moves under it. A row moves to a slot once its leading edge passes that row's middle. A drop that moves the row emits `dropped(id, from, to)`, and the page decides when to write. The Platforms page writes at once and calls `settle()`, so the row eases into its slot until the list reloads in the new order, with an 800 ms timer as the fallback. `General` reloads the moment it writes, which would rebuild the rows mid-move, so the Game page calls `settle()` first and writes the order on `settled()`, once the row is in place (`movedIds(from, to)`). Esc cancels a drag. `LATTIS_DRAG_PLATFORM` drags on the Game page too while it's the open page, with `<place>.<name>:<pixels>` (`chips.status:-150`). Appearance is short: the theme cards, a picker each for the colors and the style in use, and Save as theme. Customize (`CustomizePage`) lists every section once from `Theme.customizeSchema`, colors first and then style settings (a divider heading names each group in a section that has both). Its toolbar is search, This session (`SessionChangesPopup`; each entry says whether it is a Colors or Style change), a theme chip and Show. The chip opens a popover of two equal `ThemePickColumn`s (Colors, Style), sized by the `settings_window.theme_popup_*` settings and clamped to the window. Each column is a header with a `⋯` menu (Reset to built-in, which asks first, while a file layers on the active built-in; Rename and Delete, and Edit description on styles, for the user's own), a fixed-height list that fades at the bottom, and a New / Open file footer whose tooltips carry the key hints. Rows read `Theme.preview` (colors: four dots; style: `Theme.styleDescription` or `Theme.styleSummary` and a mini scene of the style's radii, border width, rail container and launch label on the previewed colors' background); the active row gets the selected tint and outline. The previews are re-read each time the popover opens. Show holds All / Colors / Style, a Group list (Everything, Corners, Borders, Text sizes, Spacing, Shadows, Gradients, each with its count under the other filters), and the switches Shared values only and Hide unchanged settings; its button's label names the active filters. Every filter but the search also shows in a banner above the list (`filters` in `CustomizePage`, one entry per active filter with its text, its Show label and a `clear` function): a chip per filter with its own ×, the number of matching settings and Clear all, tinted by `settings_window.filter_banner_*` (the icon is a link while a "Following …" chip is there, a filter otherwise). A group and "following" are one slot, so the banner never has both. Every filter change goes through `keepingSection()` and `swap()`, so the view stays on its section, and all of them reset when Settings opens. `reveal()` also takes `group:<name>`, `following:<section.key>` and `shared`, for screenshots. The list and rows are `ThemeSettingsList`: a row beside its title shows `SettingTag`s from the model's `linkTarget`, `followers` and `ownValue` roles (a violet "→ Small" for a setting that follows another, a green "N follow" chip that sets `following` through `CustomizePage.showFollowers()`, an orange "own value"; the link tag is clickable and goes to its target, `CustomizePage.showSetting()`; colors are `settings_window.link_tag_color`, `follow_tag_color` and `own_value_tag_color`); each row ends in one `⋯` button (always there, so an editor never moves) that opens its `SettingRowMenu`, as does a right-click anywhere on the row; `Theme.rowMenu()` supplies the menu's texts when it opens; a section with sub-headings is one card per sub-heading, each under a label and its count (the model's `subsection`, `subsectionCount`, `firstInCard` and `lastInCard` roles), and the sidebar shows them as a third level under the current section's link (`currentSubsection`, `jumpToSubsection()`). Controls read `Theme.controls.*`, menus and popups `Theme.menu.*`, and the color picker `Theme.colorPicker.*`; only what the Settings window alone draws is in `Theme.settingsWindow.*`. `NewThemeDialog` takes a description for a new style (48 characters, with a counter); `EditDescriptionDialog` changes a user style's (`CustomizePage.askDescription()`). `RenameThemeDialog` (shared the same way, from a user theme card's right-click Rename) checks the name with `Theme.nameError` as you type and says which themes and files will follow the new name. `DeleteThemeDialog` (shared with the Appearance page, where a user theme's card has an × on hover and a right-click Delete) names the file and lists the themes and files that use it, and asks again before deleting for good when there is no trash. `reveal(item, half)` scrolls to a section, for `LATTIS_OPEN_SETTINGS=customize/<section>`; `colors/<section>` and `style/<section>` also narrow the list to that half (the window's `showCategory("colors")` does the same, as Library's tag colors link does), `menu` opens the theme popover and `delete` the Delete dialog for that half, and on Appearance `appearance/hover:<theme>` shows that card's × and `appearance/delete:<theme>` its dialog. ## Components

`qml/components/` holds building blocks used across the app.

**Surface** is the universal colored panel, card, button and dialog background. When `fill` and `fillEnd` differ it draws a two-stop gradient in `direction` (`"down"` / `"up"` / `"right"` / `"left"`); when they're equal it's flat, with no `Gradient` object active.

**Icon** renders a vector icon from `Icons.qml`'s SVG path data on a 24×24 grid, scaled to `size`. `Icons.qml` holds the path strings (mostly Tabler Icons; a path starting with `stroke:` is a line icon that `Icon` strokes with `layout.icon_stroke`, round caps and joins, any other is a filled shape; the Steam, Switch and Proton platform icons are redrawn from Remix Icon) as a static QML type. The icons traced from Icons8 come from `LicensedIcons`, which has stand-ins in the public repo (`qml/components/LicensedIcons.qml`, built when `licensed/` is missing).

**Motion** is a singleton that reads the style's `[motion]` section and the General setting Reduce motion. `Motion.on` (full motion) is false when `duration_scale` is 0 or Reduce motion is set; a `Behavior` on a moving value (scale, position, size, rotation, a spring) sets `enabled: Motion.on`. `Motion.fades` is false only when `duration_scale` is 0, and `Motion.reduced` is Reduce motion itself: a `Behavior` on a fade or a color sets `enabled: Motion.fades`, so Reduce motion keeps it. `Motion.duration(ms)` scales a duration by `duration_scale` and gives 0 when motion is off; `Motion.fadeDuration(ms)` does the same for fades, which Reduce motion leaves alone. Per-element durations such as `hero.fade_duration` go through one of them. **MotionNumber** picks by its `fade` property, true for `property: "opacity"`; a `Behavior on opacity` can't tell it which property it animates, so it sets `fade: true` (`Behavior on opacity { enabled: Motion.fades; MotionNumber { fade: true } }`). **MotionColor** is always a fade, and **MotionSpring** lands at once when `Motion.on` is false. The animation types read the theme, so a call site is one line (`Behavior on scale { enabled: Motion.on; MotionNumber {} }`): **MotionNumber** and **MotionColor** take `speed` (`"fast"`, `"normal"` or `"slow"`) and the style's easing curve (`MotionNumber { linear: true }` fades at an even rate instead, for large surfaces such as `Scrim`, where the curves' steep start lands a third of the fade in the first frame and reads as a flash); **MotionPop** is an `OutBack` number animation with the style's `overshoot`; **MotionSpring** is a `SpringAnimation` with the style's `spring` and `damping`, for things that follow the pointer.

**MotionPopup** is a `Popup` that fades in while growing from `motion.popup_scale` (`PopupEnter`) and shrinks back to it while fading out faster (`PopupExit`); every dialog and popup uses it instead of `Popup`. Menus and dropdowns drop down instead: `DropdownEnter` grows them from their top edge to full height while they fade in, and `DropdownExit` folds them back up. Their entries slide down with the growing bottom edge like a drawer (the list is translated up by the hidden fraction and the popup clips it) rather than staying put under a growing window. They animate a `reveal` fraction rather than `height`, so the popup declares `property real reveal: 1`, `height: implicitHeight * reveal` and `clip: true`; `SettingsMenu` (so every context menu) and `SettingsComboBox`'s list do. A `SettingsMenu` opened from a button that's its parent can set `growFrom` to it instead: the popup keeps its full size, its background's outline grows from a sliver just under the button, as wide as it, to its own as `reveal` goes to 1, and a `MultiEffect` mask shows the entries only inside the outline (the Colors and Style pickers do this). One that opens beside what opened it or at the cursor (the rail logo's menu, the game menu, and their submenus) sets `pops` instead, so it springs out of the corner it opened from rather than dropping down from nothing: `MenuPopEnter` grows it from `motion.menu_scale` while it slides in from `motion.menu_offset` away (a `slide` property its background and list are translated by, since `popup()` owns its position), and `MenuPopExit` simply fades it out over `motion.fast`. While it closes the menu is drawn as one layer (`flatten()`, on the popup item), since faded as separate items the entries showed over whatever was behind the see-through panel; the layer is dropped once it has closed, as it softens text. `popDirection` says which way: `"right"` for a submenu or a menu beside a button, `"down"` below the cursor, `"up"` when it flipped above it, `"below"` and `"above"` for a menu right-aligned under a button (a setting's `⋯`, the game page's `menu` button) or flipped above it. A menu only flips once it has laid out its entries, after `popup()` returns, so `GameList` binds `popDirection` to the menu's `y` against the point it asked for. A menu that simply opens where it is asked to (every right-click menu: the logo's, a text field's, a theme card's, a color swatch's) sets `atPointer`, which implies `pops` and binds `popDirection` that way itself as it opens, so whoever opens it needs no code (a text field's `TextContextMenu` moves itself under the pointer as it opens, since Qt would place it at the text cursor). The entries move with the menu as one piece: a per-entry cascade made long menus slow to read. An expanding section, like a Platforms or Emulators row's fields, is an `Unfold`: its height eases between 0 and its column's while the entries fade, clipped only while it moves, and only the column hides when folded, so the wrapper keeps the width its layout gives it. A `SettingsMenu`'s `showing` is true from the moment it starts opening until it starts closing, for turning a chevron in step. While one of its entries has its submenu open (`openSubmenuItem`), the other entries take no hover, which in Qt closes the submenu at once and lost it on a diagonal path to it. Instead each entry's `HoverHandler` decides: when the pointer, from its last position (`lastPointer`), is inside the triangle to the submenu's near corners, taken 40 px past them (`headingToSubmenu()`), it is on its way there and the submenu stays, unless it rests on the entry for 300 ms; anywhere else the entry takes over at once (`SettingsMenuItem.takeOver()`: the other submenu closes, it becomes current and its own submenu opens). A new popup should be a `MotionPopup`, and a modal one dims the window with `Overlay.modal: Scrim {}`, which fades with it (the popup sets the overlay's opacity on open and close; `Scrim` animates it). `IconButton`, `LaunchButton` and `RailButton` dip to `motion.press_scale` while pressed (the rail logo dips and springs back on its own, since the menu it opens takes the pointer) and fade their fill between states. The game list's rows fade their selected color, but not while a pooled row is being reused (`fading`), which would fade from the previous game's color. Hover is one highlight behind the rows (`hoverHighlight`, a child of the list's content so it scrolls with them): it springs (`MotionSpring`, with its own `list.hover_spring` and `list.hover_damping`) to the row under the pointer, or to the game whose menu is open, and fades out over headers (whose text brightens to `list.header_hover_text` instead, so a group never looks like a game), outside the list and under selected rows, whose overlay it would add to. Coming back after it faded out, it appears in place instead of springing from where it left.

**Keeping a menu open.** Qt closes a menu whenever a direct entry's `triggered` fires, and a click reaches the button before any `MouseArea` or `TapHandler` in it. An entry with `keepOpen` (the logo menu's Behind logo options) stays a direct entry, so the keyboard still reaches it, and carries an invisible inner `MenuItem` over it that takes the mouse: that one isn't the menu's entry, so nothing closes. Enter and Space are handled on the outer entry (`Keys`), and both emit `activated`. `SettingsMenuSlider` has the same inner item under its slider for the clicks beside it, and the same wait for the pointer as `SettingsMenuItem` while another entry's submenu (Side) is open. `tests/qml/tst_menukeepopen.qml` checks the pattern in a plain `Menu`.

**CalendarPopup** is a generic month calendar in a `MotionPopup`, styled from `[calendar]`. It takes `date` (the field's date, filled with the accent), `maximumDate` (optional: later days are faint and can't be picked, and the next-month arrow is disabled on its month) and `locale` (the week's first day and the month and weekday names), and emits `picked(date)` (local midnight) before closing. It opens on `date`'s month; days of the neighbouring months show dimmed and can be picked. Keys: arrows move a day or a week, Page Up and Page Down a month (the day is kept or cut to the month's end), Home goes to today, Enter or Space picks, Escape closes. It goes below its parent, or above when there is no room. **DateTimeField** (a date field and a time field) creates one in a `Loader` on first open, from the button at the end of the date field or Alt+Down in it, passes it `maximumDate`, `value` and `locale`, and takes the time of day from the time field when a day is picked; focus returns to the date field when it closes. `LATTIS_DATE_FIELD=<yyyy-mm-dd hh:mm>[/open][/bottom][/max=yyyy-mm-dd]` puts one in the window for screenshots and the UI tests.

**IconButton** is a square icon-only button with a tooltip, a `badge` dot, and a `busy` spinner. Its look comes from `[icon_button]`; it exposes `hovered`, `badgeColor` and `hoverTint` (a color laid over the fill under the mouse) so a button with its own section can override the fill, border and radius, as the filter button beside the search box does with `[filter_button]`, whose values default to `[search]`'s. Both brighten on hover by a translucent `hover_tint` over their fill rather than a hover color, so it works on any background. **LaunchButton** is the full-width Launch button. Under the mouse its label fades in a soft shadow (`hover_text_shadow`, `_blur`, `_offset`), a `MultiEffect` layer that is only enabled while the shadow shows. With `updateState` it becomes Update (waiting), Updating (downloading) or Paused, with the `update_*` and `updating_*` colors and labels from `[launch_button]`; a click opens the game's page in Steam or its downloads. With `emulatorName` set (`GameDetails` does when `GameRunner.missingEmulator` names an emulator the `Installer` offers a route for) it reads "Install <name>" in the install colors; `emulatorStep` ("45 %", "Unpacking", from the `Installer` row's state) turns it into the updating look with that text, and the page toasts the error when the job fails. `GameDetails` handles the click itself: it opens `views/EmulatorInstallDialog.qml` (a lazily loaded `MotionPopup` in the Properties window's style, `game_editor.install_width` wide, with `WindowControls`' X). The dialog reuses `EmulatorInstallTop` (it gives it itself as the `row`), shows `EmulatorProgramField` under it, and closes when the emulator is found. A failure is shown in the dialog; with it closed, the page toasts the error.

**TagChip** draws a tag: filled normally, outlined with a leading `+` when `outlined` (an addable tag), and with a leading dot for `dot`. `removable` adds a trailing `×` with its own tooltip. `lit` fades in a lighter copy of the fill (`tags.hover_lighten`) on a layer of its own, so a recolor or a morph doesn't animate; the details pane sets it while a tag, which toggles it in the tag filter, is under the mouse. **FilterChip** is the smaller chip under the search box for an active filter. `raised`, `raiseBy` and `pressed` make the chip rise while hovered and dip while held (as transforms, so a Flow's animations stay free).

**JustifiedFlow** lays its children out in rows like a `Flow`, then makes every full row end at its right edge: the row's spare width is split equally among its chips, which widen (a `TagChip` centers its text, so the extra goes to both sides) while the gaps stay `spacing`. The list's own last row stays ragged, since stretching two chips across a card looks worse than a short row; a row cut short by `maxRows` is full and ends flush. Rows past `maxRows` are hidden, so they take no clicks, and `implicitHeight` covers only the shown rows. It packs from each child's `implicitWidth` and sets `width`, so a child's implicit width must not depend on its width.

**Toast** is the short message bar at the bottom of the main window. It slides in from the window's bottom edge (normal) and back out (fast) (`open` is whether it should show, `shown` how far it has slid; 0 off the window), like the download bar. It stays up while the mouse is on it so the optional `link` can be reached. `status` is a running job's progress, with no timer: it shows for as long as it isn't empty, and a message goes over it and hands back to it (`settle()`). The main window binds it to `ScanLookup`'s progress. `showUndo(text, token)` shows a change `Library.undoOffered` announced: an Undo link (`isUndo`) that calls `Library.undo(token)`, up for `undoDuration` (15 s); token 0 is a plain message. `undo()` runs that link, for the `undo` action (Ctrl+Z). The main window and the Settings window each have a Toast and show `undoOffered` in the window that made the change: a settings page wraps its change in `Window.window.change(fn)`, which sets `SettingsWindow.changing` so only that window's toast shows it (`Main.qml`, `SettingsWindow.qml`); the `LATTIS_UNDO=<hide|save|delete_game|delete_tag|move_platform>` hook makes one of those changes.

**Wordmark** is the horizontal logo lockup: the icon beside "Lattis", in light text on dark backgrounds and dark text on light ones (or forced with `text: "light"/"dark"`). The PNG has a margin; the item is the art's box, so it aligns with what's around it.

**AboutContent** is the About content shared by AboutDialog and Settings → General: the wordmark with the version, description, and credits. The host provides the colors. While `AppUpdate.notify`, unless `showUpdate` is false (Settings → General has its own Updates section), it shows a NoticeBar above the wordmark, "Update available <current> → <latest>", with an Update button (Open release page when the file can't be replaced) that emits `updateRequested`.

**UpdatesDialog** (`views/UpdatesDialog.qml`, an `AppDialog`, `game_editor.update_width` wide) is what the Lattis update and the emulator updates share: everything but the title, the footer and where each row's state comes from. `rows` is `[{id, name, from, version, size, notes}]`; `stateOf(id)` gives `{status, progress, step, error}` (`status` is `pending`, `waiting`, `active`, `failed` or `done`), and `updateRequested(id)` fires from a row's Update and Try again. One row is plain notes with "<from> → <version> · <size>" under the title (`subtitle` replaces it, `showNotes` folds the notes away) and an `InstallProgress` while active; several are the Platforms page's list (one `settings_window` card, rows told apart by lines, a hover tint on the header, the open row on `OpenRowCard`'s darker panel, its notes in an `Unfold`, one open at a time in `openId`) with a chevron, name, versions and the state on the right. The dialogs built on it set `title`, `rows`, `stateOf` and `footer`.

**UpdateDialog** (`views/UpdateDialog.qml`, lazy, an `UpdatesDialog` with one row for Lattis) shows what `AppUpdate` is doing: "<installed> → <new> · <size>" under the title, the release notes (the release body in the shared card, as tall as the notes, scrolling when the dialog runs out of height), and Update, Skip this version and Later; while downloading an `InstallProgress` and Cancel; when ready "Lattis <version> is ready" with Restart now (off with "Close <game> first" while a game runs) and Later; a failure under the notes with Try again; Open release page instead of Update when `AppUpdate.canReplace` is false, with `replaceBlocker` saying why. `Main.qml`'s `openUpdate()` opens it from the app menu's "Update to <version>" entry (the `update_app` run name, which is not a shortcut), About, and Settings → General (`GeneralPage.openUpdate` → `SettingsWindow.openUpdate`). The rail logo's dot (`rail.update_dot*`: colors, size, `update_dot_corner` and `update_dot_margin`; `AppUpdate.notify` or a non-empty `Installer.updates`) and the menu entries only read `AppUpdate` and `Installer` once the first frame is out (`Rail.startedUp`). Below the app's entry, one entry opens `EmulatorUpdatesDialog` for the emulators with a newer release: "Update <emulator> to <version>" for one, "Update N emulators" for several, and "Updating …", disabled, while they all download. Settings → General's Updates section (shown when `AppUpdate.available`) has the `check_for_updates` switch, the status and Check now / Update.

**EmulatorUpdatesDialog** (`views/EmulatorUpdatesDialog.qml`, lazy, an `UpdatesDialog`) shows the emulator updates the app menu entry offers. `Main.qml`'s `update_emulators` run calls its `show()`, which snapshots `Installer.updates` into `rows` (so a row stays once its update is done) unless updates are still running, when it keeps the rows and the queue. Its footer has Later and **Update all** (primary), Cancel while anything runs, and Done once nothing is left to update. A row's status comes from `statusOf(id)`, read from `Installer.emulators` and the queue: `active` (any job state but idle and failed), `waiting` (in `queue`), `failed`, `pending` or `done` (no `updateVersion` left). Updates run one at a time: `enqueue(ids)` adds to `queue` and `pump()` calls `Installer.update(id)` for the next one whenever none is active, on every `emulatorsChanged`; `cancelAll()` empties the queue and cancels the active job. The cards leave room for the scroll bar only while the list scrolls, so their margins match when it doesn't. Closing the dialog doesn't stop the queue (the Loader stays active), and `Main.qml`'s `emulatorUpdated` shows no toast while the dialog is open, since it shows the result itself. A game running in the emulator fails that row with "Close <game> first", and Try again runs it once the game is closed.

**WhatsNewDialog** (`views/WhatsNewDialog.qml`, lazy, same look as UpdateDialog) shows the saved release notes of the version just updated to; `Main.qml`'s `showWhatsNew()` opens it from the "Updated to <version>" toast's What's new link after the first frame (not on a first start, which shows the setup guide).

**KeyedListModel** is a `ListModel` for a short JS array that animates (the filter chips, the rail's platforms): set `source` to an array of objects with a unique `key` and it applies only the inserts and removes, so a positioner's `add` and `move` transitions play for the entry that changed. A removed entry stays with `leaving: true` for `leaveSpeed` (its delegate plays its exit in that time: the filter chips, the rail's platforms and the tags in the details pane and the tag editor play their pop backwards with **PopLeave**) and then leaves; `leaving` on the model says one is on its way out. An entry brought back within that time (a chip turned off and on again, a tag removed and added back) stays, with `leaving` false again. So a delegate hands its entry's `leaving` to its `PopLeave` (`leaving: chip.leaving`) rather than starting it: PopLeave plays the exit when it turns true and, when it turns false, stops the exit and pops the entry back to full opacity and scale, as it would enter; a delegate that started the exit itself and ignored the way back left an unseen entry with a gap in the row. With `animated` false (no motion, or the view not ready yet) both ways snap, still through the animation, so a binding on the target's opacity (the rail button's drag) survives. A different order of the entries that stay replaces everything and sets `rebuilt` for a moment, which the transitions check so the delegates don't enter again. So does a `source` with a new `scope` (set before `source`): the details pane's tags are scoped to the game, so another game's tags replace them at once while a tag added to the same game pops in. A new scope with exactly the same entries keeps them as they are, with nothing made again. A `source` set again before the event loop comes back still counts as the new scope and replaces everything rather than animating: during a game switch the first one can come from bindings still on the previous game (the game page's Steam chip), and the correction would have shown that entry leaving. `rebuilt` is set before the entries are made, so a delegate that plays its own entrance (the game page's chips) can check it when it's created. Delegates read their entry as `required property var model`. **AppLogo** draws the rail logo in the style `rail.logo_style` names: the simple mark, the mark on a colored square, or the wordmark.

**Tooltips** are the attached `ToolTip`'s one shared instance, and the Basic style gives it no transitions: `Main.qml` assigns its `enter` and `exit` (fades over `motion.fast`) after the first frame, since making that instance earlier would delay it. **FadeImage** is an `Image` that fades in (`MotionNumber`, fast, linear) when an asynchronous load finishes; an image that is ready at once shows at once. With `retainOnResize` a new `sourceSize` keeps the shown picture until the new one is decoded (`retainWhileLoading`); a new source still clears it. `fades: false` shows a picture that loads out of sight without the fade, and `arriving` is true while it loads or fades in, for whatever stands in for it to stay until it's done. Grid covers, game icons, art thumbnails and the art browser, Detailed lookup and lookup row pictures use it. The game editor's `Hint` is an `Unfold`: set `open` instead of `visible`, so a note that appears while the editor is open unfolds.

**ActionShortcuts** is a thin `Item` that creates one `Shortcut` per action a window handles (see [Named actions](#named-actions)).

**WindowControls** draws the minimize/maximize/close buttons for frameless windows. In `dialog` mode only close shows. **WindowFrame** puts resize edges around a frameless window.

**StatChip** is the small label/value chip next to Launch (a field of the game, or a Steam chip). With `tipStars` (a rating, `-1` for none) its tooltip shows stars instead of text: its own `ToolTip`, made by a `Loader` only for that chip, since the shared one shows text only. With `attention` it shows in notice colors, or the outline and icon in `attentionColor` (the Steam update chip uses the Launch button's update color). `iconTint` sets the icon's color (the ProtonDB chip's tier color, `stat_chip.protondb_<tier>`) over the normal and hover colors, but not over `attention`. With `clickable` it takes a hand cursor, can change its label, value and icon colors under the mouse (`stat_chip.hover_*_color`, which default to the resting colors, so nothing lights up unless a theme sets them) and dips to `motion.press_scale` while pressed, as a whole, and emits `clicked` (the play time chip opens play history).

**NoticeBar** is the thin status bar for a lasting state (a read-only library), with action buttons as its children. Its text can come as `parts` instead: pieces marked `chip` (file names, from `Backups.notice`) are drawn as chips, and the bar clips rather than elides.

**SavesPanel** (`SavesPanel.qml`) is the backups list in a game's Properties (for a ROM game the emulator's: `emulator` in the state shows a note that they are shared, and an empty state has no match or folder buttons), at the top of the Saves card on the Saves tab (`EditorSavesPage`, `game` set from the editor; Back up now, `GameSaves.backUpNow`, is a button on its **Backups** heading, a plain one so Save stays the only primary). `GameEditor` calls `GameSaves.open(game.id)` when it shows the game, and the panel shows `GameSaves.state` for that game: a row per backup (its name with a disk icon, or else its date, then the size, rename (`GameSaves.rename`), delete (`GameSaves.remove`, to the trash) and **Restore**, which asks inline, then `Backups.restoreGameSaves`, refused with the toast while a game runs), the "Keeps the last…" line (singular and plural written out) and a line saying these act at once while mod manager links wait for Save. With nothing to show (`empty`) it holds the "No saves found" state, whose **Change match** emits `chooseRequested`; otherwise `EditorSavesPage`'s match row, under the own save locations, has what matched and **Change match**. **SavesGamePicker** (loaded on first use by `GameEditor`'s own `Loader`: `chooseSavesGame()`) is a search of the Ludusavi index; a pick is remembered as `saves_game`, "Use the automatic match" clears it. A finished `game-saves` Import reloads the panel.

The **Last backup** chip is `GameDetails`' `lastBackupChip`: off by default, shown only for a game with a backup, with the date and the name when it has one. `GameDetails` asks `GameSaves.loadLast(game.id)` when the game changes while the chip is on; it never reads the Ludusavi index.

**MediaRow** (`MediaRow.qml`) is the Media section of a Steam or ROM game's page (a ROM game's tiles are its emulator's screenshots): a `CollapseHeading` ("clips"), a horizontally flicking row of thumbnails (16:9 from `media.thumb_height`; a clip's has its length with a play icon (`media.badge_icon_size`) and a scrim from `media.thumb_scrim`, a screenshot's is the picture alone; a picture narrower than `media.thumb_fit_below` (a 3DS shot of both screens) is shown whole instead of cropped; edges faded by `media.edge_fade`) and its own scroll bar. It asks `Library.media(game.id)` when the game changes and fills `items` from `mediaReady`; `shown` drops the clips when `General.showVideo` is off and the screenshots when `General.showScreenshots` is off, and `strip` keeps the first `General.mediaLimit` of them (0 = all) so a game with hundreds builds only that many tiles; when some are left out a "+N more" tile ends the row, over the next hidden thumbnail blurred by `media.more_blur` and covered by `more_scrim` at `more_scrim_opacity` (`more_hover_scrim` at `more_hover_scrim_opacity` under the pointer; `more_background` until it loads, `more_text`, `more_font_size`), and emits `showAllRequested` like **Show all**. Pictures and videos from the game's own media folders are mixed in (a video, `kind` `video`, is a clip as far as the tile is concerned; `show_video` hides them and `show_screenshots` only the pictures); `mediaLimited` shows "Showing the newest 2000" under the heading. It is hidden when the game is not Steam's, Proton, Linux or a ROM game, `General.showClips` is off (the section is not in `[game_page] sections`) or nothing is shown. **Show all** (`media.link_color`, `link_hover_color`) sits at the right end of the heading row, `media.link_inset` (6) in from the card's right edge,, which emits `showAllRequested(game.id)`; `GameDetails` passes it up as `galleryRequested`, and `Main.qml` answers with `setGalleryOpen(true, id)`. A click on a tile emits `mediaRequested(item, shown)` and a right click `menuRequested`, which `GameDetails` passes up; it opens the viewer through `showMedia()` and opens **ClipMenu** (Show in folder, `Library.showClipFolder`). While `FfmpegTool` has no ffmpeg and the row has a clip it shows **FfmpegPrompt** above the tiles: what ffmpeg is for, the download size, **Install ffmpeg** and **Not now** (`installDismissed` hides it for the session), then the install's progress with **Cancel**, or its error. The tiles still open the viewer, which shows the same prompt in place of the video.

**FriendsPanel** (`FriendsPanel.qml`) is a `Surface` in `GameDetails`' right column between `InfoPanel` and `AchievementsPanel`, styled by `[friends]`. It shows only for a Steam game (`appId` from a `steam-<id>` game id) when `General.friendsGroups` isn't empty and `FriendsActivity.forGame(appId)` has someone in a shown group; `reload()` runs when the game, `wanted` or `FriendsActivity.changed` changes. A friend in the game is listed once, under Playing now, while that group is shown. The top shown group's heading (`topGroup`) sits in the header beside View all, so the panel has one title. Playing now and Played recently (at most `friends.recent_max`, `friends.recent_columns` side by side) are rows of picture, name and hours; Played previously is a row of pictures with the name and hours in the tooltip. A click opens a chat (`openChat()`), View all `openFriendsWhoPlay()`. While `wanted`, a one-minute timer calls `refreshPlaying()` (the singleton limits it). Right-click emits `menuRequested`, which opens the page menu with the three group ticks (`General.setFriendsGroup()`).

The `friends_playing` field in `GameFields` is the chip and info row: `FriendsActivity.playedCount()` for a `steam-<id>` game, `"N play"`, empty (so hidden) at 0; it follows `FriendsActivity.changed` only while a chip or row asks for it, and it isn't clickable.

**MediaViewer** (`MediaViewer.qml`) plays a clip or shows a screenshot. It is a `MotionPopup` in a `Loader` that `GameDetails` activates on the first one opened, so the QML side of Qt Multimedia costs nothing before then (the library is linked for the video thumbnails, but nothing in it runs before a video item is listed). A `video` item (a plain file from a media folder) sets `file` from the item and plays it as it is, with the same controls but no `prepare()` step, no ffmpeg prompt and no `discardClip` (`isSteamClip` is a Steam clip, `isClip` any item that plays; `tempFile` guards the delete so a user's own file is never removed). `MediaTile` shows a video's thumbnail and length from the item, swapping them in when `Library.videoThumbnailReady` arrives, and `Icons.filmLine` on the tile colour until then. `show(item, list)` keeps the row's list so `step(±1)` can move to the previous or next item (the ‹ › buttons, `media.viewer_arrow_inset` from the window's sides, Page Up/Down, or Left/Right on a screenshot; on a clip Left/Right seek). A screenshot is an `Image` decoded at the size shown (its own size once zoomed), with no bar under it; the wheel zooms it toward the pointer up to `maxZoom` (`zoomTo`), a slider on a pill in its bottom right corner (the same `Bar` as the seek bar, shown and hidden with the bars) sets it, a drag pans (`panBy`, clamped to the picture), `+` `-` zoom from the middle, `0` and `step()` reset (`resetZoom`); its `picture` rect places the bars as the video's does. For a clip, `prepare()` calls `Library.prepareClip`, which joins the clip into a temp MP4 (see [steam](steam.md#clips-and-screenshots)); the player starts when `clipPrepared` answers for the current `token`. `discard()` stops the player, empties its source and calls `Library.discardClip`; it runs on every close and before each new clip, so closing mid-play or opening another clip leaves no temp file. The bars lie over the picture (`bars`, sized to `picture`, or the whole area when there is none, so ✕ stays reachable; hidden until `settled`, so they don't jump when the first frame lands), each over a gradient (`EdgeShade`, `media.viewer_bar_scrim`, reaching `viewer_bar_scrim_reach` past it). The top bar has the date and "n of N" and ✕; the bottom one, on a clip, a seek bar (it thickens under the mouse, shades up to the pointer and shows that time above it) over one row of `ControlPill`s (a dark shape per group, `media.viewer_pill_*`: a circle around a lone button, a pill around the skips, the volume, which widens as its slider slides out, and the time): play/pause, ±5 s, volume (a speaker whose slider slides out under the mouse; the level is kept in `[general] clip_volume`), the time as `0:01 / 0:32`, and fullscreen at the right (a fullscreen the viewer turned on is turned off again when it closes). Playback pauses 100 ms before the end to keep the last frame, and play then restarts it. `barsShown` hides the bars and (over the video) the pointer `media.viewer_hide_delay` ms after the last mouse move or key (`wake()`, from a `HoverHandler` on `bars`, so only movement over the picture counts; leaving the picture hides them at once), but not while a clip is paused or loading, the pointer is on a bar, or the menu is open. The ‹ › buttons fade with them only while the pointer is over the picture; outside it they stay. Keys, and a click on the video, flash a sign in the middle of the picture (`flash()`, `media.viewer_flash_*`): play or pause, the skip, or the volume icon with its percentage; it only fades, so repeated keys don't feel slowed. Keys: Space play/pause, Left/Right ±5 s, Up/Down volume, M mute, F fullscreen, Esc leaves fullscreen first, then closes. Clicking outside the video closes the viewer; a right click opens ClipMenu. Every size and color is a `media.*` theme setting. With `games` set (the Gallery does), an item that carries a `gameId` gets the game's platform icon and name in the top bar, over the date (the two lines on a pill like the bottom bar's; Go to game and ✕ have one too), and Go to game beside ✕, which closes the viewer and emits `gameRequested(id)`; `index` tells items apart by `gameId` as well as `id`, since two games' Steam screenshots can share a file name. A star button left of Go to game (in its place on a game page's viewer) toggles the item's favorite mark, filled and in `icon_button.icon_active` when on; `Ctrl+D` (`Actions.keys.toggle_favorite`, handled through `Actions.triggered`, which Main.qml's `run()` ignores while a viewer is open) does the same, and `ClipMenu` has Add to / Remove from favorites above Show in folder. All three read `Library.isMediaFavorite(path)` with `mediaFavoriteRevision`.

**AchievementsPanel** (`AchievementsPanel.qml`) sits in `GameDetails`' right column (`side`, by default below `InfoPanel`) (below the description in the compact layout), spaced by `achievements.gap`. It shows only for a Steam game with `General.showAchievements` on and at least one achievement: `reload()` calls `Library.achievements(game.id)` when the game or `wanted` changes and `onAchievementsReady` fills `items`. The header has the title, the count (`complete_color` once all are unlocked) and a progress bar, with a medal (`trophy_size`) before it once all are unlocked (the viewer's summary does the same); the grid fits `perRow` icons per row for `achievements.max_rows` rows, and "Show all (n)" appears when more exist. Each icon is an `ArtThumb` of `modelData.icon` (gray ones at `locked_opacity`, a medal icon when it can't load); a hidden locked one shows "?" and loads nothing. Steam's CDN answers 503 to a burst, so icons start three past the number already settled (`settledCount`) and a failed one retries up to 5 times at growing intervals. The tooltip is one `AchievementTip` (a `ToolTip` with its own content, like Steam's) shared by all tiles: `tipTile` is the tile under the pointer, and the tip keeps its last item while it fades out. A header band holds the icon, name and description (the hidden text and a "?" for a hidden locked one); below it are "Unlocked <date>" or "Locked" and the share of players, in `tip_rare_color` under `rare_percent`. Its sizes and colors are the `tip_*` settings. A click anywhere on the panel calls `openViewer()`, which activates the `Loader` on `AchievementsViewer` the first time.

**RareGlow** (`components/RareGlow.qml`) is the gold glow behind an unlocked rare icon (`percent < rare_percent`); the panel's tiles, the viewer's rows and the tooltip's icon each add one as a child of their `ArtThumb` (`anchors.fill: parent`, `active`, drawn at `z: -1`, so the thumb must not clip). A rounded rectangle in the glow color, blurred by a `MultiEffect` layer, in a `Loader` that only exists while it shows. Locked icons never get one, so the thumb's dimmed opacity doesn't fade it. Sizes and colors are the `achievements.rare_glow_*` settings.

**IconWall** (`components/IconWall.qml`) is the tilted, scrolling wall of images the setup guide's cover wall was extracted into. `sources` is a list of URLs, repeated to fill the rows; tile size, `gap`, `tileRadius`, the three rotation angles, `speed`, `decodeSize`, `tint`, `dim` and `vignette` are plain properties whose defaults give the setup guide's wall, so `SetupCoverWall.qml` is only that list of bundled covers. Each source is decoded once by a hidden `Image` (`ready` once all have settled, then the wall fades in); a source that fails after `retries` tries lands in `failed` and the tiles use only `good`, so no tile is left empty. `concurrency` above 0 starts that many sources past the number already settled, for a server that answers a burst with errors (Steam's CDN); 0 loads all at once. The scroll distance runs to 1,000,000 px, which keeps the loop's duration in milliseconds inside Qt's 32-bit range at every speed.

**AchievementsViewer** (`AchievementsViewer.qml`) is a full-window `MotionPopup` like the media viewer, loaded on first use. `show(game, items)` resets the search and filter and reads the recent play time from `Library.pageHistory` for the summary. The list is `matches`: the items passing the search (name or description) and the All / Unlocked / Locked filter, each with a `group` (0 unlocked, 1 locked, 2 hidden) and sorted by it into a `ListView` with section headings and counts. Hidden locked ones are replaced by a single summary row until revealed (`hiddenShown`; a search never matches them). Its sizes and colors are the `achievements.viewer_*` settings; the search box and filter take theirs (`viewer_filter_*`) through the color properties of `SettingsTextField`, `SettingsSearchField` and `SettingsComboBox`, which default to `controls.*`. The card has the game's `Backdrop` behind its content (`flat`, fading into `viewer_background`, rounded to the card by a mask), sharing every `backdrop.*` setting, so `backdrop.enabled` turns it off here too. The summary card shows a medal (`viewer_trophy_size`) before the text and bar once every achievement is unlocked, and "N rare" (unlocked ones under `rare_percent`) at the right of the text line. Its backdrop is set apart from the main window's: `Backdrop` takes `strength` and `saturation` (default `backdrop.opacity` and `backdrop.saturation`), and the viewer passes `viewer_backdrop_opacity` and `viewer_backdrop_saturation`. The name, year and play time carry a drop shadow (`viewer_text_shadow*`, a `MultiEffect` layer on their column) so they read over a light backdrop; their muted colors are lighter than `text_muted`, as a shadow smears text that has little contrast with it. Once every achievement is unlocked (`complete`), the medal (`viewer_complete_color`) and the bar (`viewer_complete_bar_fill`) turn Steam blue, and an `IconWall` of the newest `wall_icon_count` unlocked icons (the same URLs as the list, so they come from the cache) sits behind the summary card's content: wall at `wall_opacity`, then a left-to-right `wall_gradient_left` to `wall_gradient_right` tint and a top-to-bottom `wall_gradient_top` to `wall_gradient_bottom` fade, all clipped to the card's corners by a mask. The wall loads only for a complete game with the viewer open (`active` follows `visible`) and is turned off by `wall`, still by `wall_motion` and Reduce motion.

**DownloadBar** is the bar pinned to the bottom of `GameDetails` (a `Loader`, active only while `Library.download` is not empty and `download_bar.show` is on) while Steam downloads a game: the game's icon (the Steam icon without one), the label (Updating, Installing, Paused), the name, the percentage and a progress bar that animates to each value (`fill_duration`). A click opens Steam's downloads through `GameRunner.update()`; its error is its `message` signal. A chevron (`chevron_size`; 0 = none) sits after the percentage in the name row, always shown, with its own click area above the bar's; it emits `collapse()`.

**DownloadPill** is what's left in the bottom-right corner of `GameDetails` (a `Loader` next to the bar's) while the bar is hidden (`General.downloadBarCollapsed`): the download icon (`pill_icon_size`, `paused_fill` while paused), the percentage and a chevron up, on the bar's colors with `pill_radius` (the bar's `radius` by default). It emits `expand()` and doesn't open Steam. `GameDetails` animates `slide` (0 bar, 1 pill) over `collapse_duration`: the bar morphs into the pill (one rect shrinking toward the bottom-right corner, lowered so the percent and chevron row stays put) while the bar fades out over the opaque pill beneath it and the download symbol travels from the bar's game icon to its place in the pill, and tooltips stay off until it settles, and both `Loader`s stay active while a download runs (the pill's width is known before the morph starts, so nothing jumps on its first frame). `flick` makes room for whichever shows.

**GameIcon** shows the small game icon: art from `art/<id>/icon.*` if present, otherwise a tile in the game's hue (`list.icon_placeholder_*`) with the first letter. Both have `list.icon_radius` corners; the art is masked only once loaded.

**ArtPlaceholder** is what a game without hero art shows instead: a gradient in the game's hue, from left to right, with the `hero.placeholder_*` settings. The hero and the backdrop both use it, so they always match.

**`Args.js`** splits and joins program argument strings as typed in a text field, like a shell does: an argument can have quoted parts anywhere in it (`--config="My Config.ini"`), and a quote without its closing one is kept as a character (`it's`). Joining quotes an argument that has spaces or quotes in it, with the kind of quote it doesn't contain.

## Reference

### Main.qml

Functions other parts of the app call on the main window (through `window`):

| Function | What it does |
|---|---|
| `launch(game)` | Launches a game; handles Locate, Steam install, pending edits |
| `openSettings()` | Opens the settings window |
| `openSettingsAt(category, item)` | Opens settings at a category and optional item |
| `openSetup(step)` | Opens the setup guide at step 0 (Welcome) |
| `openBulkLookup(from, forTags)` | Opens "Look up missing info"; `from` is returned-to window |
| `editGame(id)` | Opens the game editor for `id` |
| `addGame()` | Opens "+" file picker, then the editor |
| `selectGame(id)` | Selects a game in the list |
| `hideGame(game)` | Hides a game (`Library.removeGame`); the toast's Undo comes from `undoOffered` |
| `uninstallGame(game)` | Uninstalls a game (hands to Steam, or dialog) |
| `run(name)` | Handles a named action |
| `runOn(name, game)` | Handles a "selected game" named action on `game` |

Screenshot hooks (`LATTIS_*` env vars) call private functions (`selectAndLaunch`, `selectAndEdit`, etc.) from `main.cpp`; each hook is described in the comment above them in `main.cpp`.
